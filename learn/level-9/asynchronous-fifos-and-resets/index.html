9.4 Asynchronous FIFOs and resets

Teaches Asynchronous FIFO (circuit), Reset synchroniser (circuit). About 6 minutes.

A handshake carries one value per round trip. To carry one value per cycle between two clocks, use an asynchronous FIFO: a memory written on one clock and read on the other, whose values come out in the order they went in (first in, first out). Each side counts its place and needs the other's count, so that the writer never overtakes the reader.

Counts in Gray code

A count crossing through synchronisers has lesson 9.2's problem: its bits can arrive at different edges. So each side shows its count in Gray code, where the next value differs in one bit only. A synchroniser that catches a change sees the old count or the new one, never a mixture. Listing 1 is the write side of afifo, a 16-place FIFO, turning its binary count, wbin_next, into Gray code.

In line 31, each bit of the Gray code is a bit of the count exclusive-or (lesson 9.3) the bit above it: >> shifts right, moving every bit one place down, with a 0 at the top.

Each side's full or empty flag is a register worked out from the other's synchronised count, so it is a few edges late: it can say full or empty a little too long, never too briefly.

Telling Vivado

This level's project makes a second clock from the board's with the FPGA's clock manager, the MMCM (mixed-mode clock manager). Two clocks from one oscillator keep a fixed relationship, and Vivado times every path between them against their closest pair of edges, which a synchroniser's input fails. Clock groups (Listing 2) tell Vivado to leave those paths untimed, and its CDC report checks each for a synchroniser. A FIFO's Gray count also needs set_bus_skew, to keep its bits within a clock period of each other (UG903).

A reset crosses too

A reset from a button is an asynchronous input like any other: let go near an edge, it could leave some flip-flops still reset and others running. A reset synchroniser (Listing 3) sets its two flip-flops at once through their asynchronous preset, which sets a flip-flop to 1 without waiting for an edge, as lesson 2.3's asynchronous reset clears one to 0. When the reset ends, they take 0 one after the other at clock edges, so everything it resets leaves reset at the same edge.

Questions

Question 1 of 3. Put the steps in order

A Gray-code count changes one bit at each step. Put these five 3-bit values in the order the count takes them, starting from 000.

  • 011
  • 010
  • 000
  • 110
  • 001
Show answer and explanation

In order:

  1. 000
  2. 001
  3. 011
  4. 010
  5. 110

From 000, each step changes one bit: 001, 011, 010, then 110. Counting in binary instead, 001 to 010 changes two bits at once, and a synchroniser that caught that change halfway could see 011 or 000: a count one step ahead or one step back, not the one the counter holds. A reader that took 011 for the writer's count would read a place not yet written.

Question 2 of 3. Predict rst

This is lesson 9.4's reset synchroniser, rst_sync. arst has been 1 for a while, so rst is 1. arst falls 2 ns after the edge that starts cycle 1. Set rst for every cycle.

Question 3 of 3. Predict rempty

This is afifo, empty, with the read clock rclk drawn as the cycles. The writer stores its first value in cycle 0, on its faster wclk, and its write pointer changes at that edge. rempty is a register on rclk, worked out from the write pointer once the read side's two synchroniser flip-flops have taken it. Set rempty for every cycle.
