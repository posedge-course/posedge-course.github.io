9.1 Metastability

Teaches Metastability (primitive). About 5 minutes.

Every flip-flop on one clock takes its input at a rising edge, and Vivado checks that each path between them changes well clear of the window around the edge (lesson 8.1). Some inputs it cannot check. A button changes when someone presses it. A flip-flop on another clock changes on that clock's edges, which drift past yours. Such an asynchronous input will, sooner or later, change inside the window.

Neither 0 nor 1, for a while

Then the flip-flop may take neither value cleanly. Its output can hang between 0 and 1 and settle a moment later, to 0 or to 1, with no telling which: metastability. It usually settles far sooner than a clock period, and the longer you wait, the less likely it is to still be undecided, though never certain.

A simulation of your code cannot show this: its flip-flops take a clean value however close the change. So Figure 1 is drawn from a model, meta_dff, written for this course and set beside level 2's dff on the same input: it goes to X when d changes less than 1 ns from an edge, and settles 4 ns later to a value the testbench chooses.

Why it matters

A hang that has not settled by the next edge reaches the flip-flops that read it. If two of them read it, one may take 0 and the other 1, and logic that should agree with itself does not: a state machine can land in a state it never chose. So an asynchronous input goes into one flip-flop, and nothing may read that flip-flop until it has had time to settle. Lesson 9.2 builds that.

Vivado's timing report cannot find these inputs for you by checking them: it has no clock to time a button against, and only notes that such an input is there.

Question 2 of 3. Read the report

press_count_top is level 9's project on the board: presses of BTN0, counted on a second clock. Its inputs are clk, the board's clock, and two buttons, btn and rst_btn. Below is one of the checks at the start of its timing summary.

vivado/reports/press_count/arty-a7-100t/timing_summary.rpt, lines 87 to 91. Written by Vivado.

875. checking no_input_delay (2)88------------------------------89 There are 2 input ports with no input delay specified. (HIGH)9091 There are 0 input ports with no input delay but user has a false path constraint.

How many inputs does the report say Vivado has no timing for?

Show answer and explanation

The report says 2.

2: the two buttons. Vivado checks paths that start at a flip-flop on a clock it knows, and a button changes whenever someone presses it, so there is nothing to check it against: the report notes the two inputs and moves on. An input delay would be a constraint saying when an input changes after a clock edge, and a button has none to give. Sooner or later a press changes inside a flip-flop's window, and the flip-flops that first take a button must be built for that (lesson 9.2).

Question 3 of 3. Put the steps in order

BTN0 goes into one flip-flop, and that flip-flop's output into two flip-flops of a state machine, all on one clock. Put in order how one press can leave the machine in a state its diagram never reaches.

  • At the next edge, two flip-flops read it: one takes 0, the other 1.
  • That flip-flop's output hangs between 0 and 1.
  • BTN0 changes inside the window of a flip-flop that takes it.
  • The state machine those two make up is in a state it should never reach.
Show answer and explanation

In order:

  1. BTN0 changes inside the window of a flip-flop that takes it.
  2. That flip-flop's output hangs between 0 and 1.
  3. At the next edge, two flip-flops read it: one takes 0, the other 1.
  4. The state machine those two make up is in a state it should never reach.

It starts with a change inside the window, which nothing prevents for a button. The first flip-flop may hang; if it has not settled by the next edge, the two flip-flops that read it can each take a different value, and together they hold a state the next-state logic never chose. Lesson 9.2's synchroniser gives a hang a whole cycle to settle before anything reads it.
