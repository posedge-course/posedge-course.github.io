Level 9

Level 9 project A press passed between two clocks

Write press_count in my_press_count.sv until press_count_tb.sv prints TEST PASSED; on the board, LD4 to LD7 count the presses of BTN0 in binary. About 50 minutes in simulation.

The Arty has one clock, 100 MHz, but the FPGA can make others from it with its clock manager, the MMCM (UG472). This project uses two: the button is debounced on the board's clock, and the presses are counted on a second clock of 29.963 MHz that the MMCM makes from the first. The two keep a fixed relationship, but each edge of one falls at a different distance from the other's, and some come within a fraction of a nanosecond. Each press must cross from one to the other once, never twice and never not at all. It uses every lesson of this level, and level 4's press.

The design

The ports of press_count
PortDirection and widthWhat it is
clk_ainput, 1 bitthe clock the button is read on
rst_ainput, 1 bitclk_a's reset, 1 at an edge to reset
btninput, 1 bitstraight from the button: it bounces
clk_binput, 1 bitthe clock the count runs on
rst_binput, 1 bitclk_b's reset: count to 0
countoutput, 4 bitspresses so far, on clk_b
The parameters of press_count
ParameterDefaultWhat it sets
PBITS20press's counter width
HOLD999_999how long press waits for the button to settle: about 10 ms at 100 MHz

The file you write is my_press_count.sv; the module inside is press_count, the name the testbench uses. The testbench runs clk_a at 100 MHz and clk_b with a period of 33.376 ns, close to the board's second clock, and sets press small, so that a press settles in a few cycles.

On the board, press_count_top.sv wraps your design: an MMCM makes clk_b, and a rst_sync for each clock turns BTN1 into rst_a and rst_b (lesson 9.4). It leaves the MMCM's LOCKED output unused, because the count cannot change before the first press. A design for real use holds clk_b's domain in reset until LOCKED is 1: the MMCM can take up to 100 µs to make a steady clock.

What you see when it works

  • The run prints TEST PASSED: three presses count 1, 2 and 3, a reset of clk_b's side sets the count to 0, and one more press counts 1, each change at a rising edge of clk_b, however much the button bounced.
  • In the reports: the timing summary meets every constraint, and the CDC report lists one crossing, from level_a into the synchroniser, 2 flip-flops deep, covered by the clock groups.
  • With the board: each press of BTN0 adds 1 on LD4 to LD7, and BTN1 sets them all off.

If it fails

  • syntax error, followed by Invalid module instantiation: the command lacks -g2012. Add it.
  • Unknown module type: press_count: the module in my_press_count.sv has another name. It must be called press_count.
  • pulse_cross.sv:22: error: Unknown module type: sync2: a file is missing from the command. All seven must be named.
  • TEST FAILED: count=x, expected 0 at 170 ns: nothing sets count at the start. Set it to 0 when rst_b is 1.
  • TEST FAILED: count=0, expected 1 at 750 ns: no press reached the count. Count pulse_cross's pulse_b, not the pulse on clk_a, which clk_b's edges can miss.
  • TEST FAILED: count=3, expected 1 at 750 ns: the count runs on clk_a, and sees each pulse_b, one cycle of the slower clk_b, for three of its cycles. Count on clk_b.
  • TEST FAILED: count=3, expected 0 at 1969 ns: the count is reset by rst_a. It runs on clk_b, so it takes rst_b.

These messages are from Icarus Verilog 12.

On the board (optional)

You need an Arty A7 and Vivado for this part. Everything above works without them.

The board steps use Vivado's project mode, as in the earlier projects. If Vivado reports that a timing constraint is not met between sys_clk_pin and clk_b, check that the saved press_count.xdc is in the project: its clock groups line tells Vivado not to time those paths, which cross through synchronisers. If the LEDs count more than once for a press, check that your count takes pulse_cross's pulse_b; if they never change, that BTN0 is btn.

Your checklist

Simulation path

  1. Make a new folder and save the nine files listed above into it. press_count_tb.sv is the specification. The last three are for the board path: the top that makes the second clock, the reset synchroniser, and the constraints.
  2. Make a file my_press_count.sv with a module named press_count, the two parameters in the second table with their defaults, and the six ports in the first.
  3. Inside, place a press (level 4's project) on btn, clocked by clk_a and reset by rst_a, with BITS set to PBITS and HOLD to HOLD. Its pulse is one cycle of clk_a for each press.
  4. Place a pulse_cross (lesson 9.3) that carries that pulse from clk_a to clk_b, with rst_a as its reset.
  5. Add the 4-bit count, on clk_b: 0 at an edge where rst_b is 1, and 1 more at an edge where pulse_cross's pulse_b is 1.
  6. Run iverilog -g2012 -o count_sim press_count_tb.sv my_press_count.sv pulse_cross.sv sync2.sv press.sv debounce.sv edge_detect.sv, then vvp count_sim, until it prints TEST PASSED.
  7. Open press_count_tb.vcd and add clk_b, btn and count. Check that count goes up once for each press, at a rising edge of clk_b, however much btn bounces.

On the board (optional)

  1. In Vivado, create an RTL project for xc7a100tcsg324-1 with my_press_count.sv, the five other design files of the run step, press_count_top.sv and rst_sync.sv, and the saved press_count.xdc. Make press_count_top the top module, then run Generate Bitstream.
  2. Open the timing summary and check that every constraint is met. Then type report_cdc -details in Vivado's Tcl Console and find the one crossing from sys_clk_pin to clk_b.
  3. Program the board, then press BTN0 a few times: LD4 to LD7 count the presses in binary. BTN1 sets the count back to 0.
