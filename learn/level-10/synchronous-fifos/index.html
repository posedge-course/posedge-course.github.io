10.2 Synchronous FIFOs

Teaches FIFO (circuit). About 6 minutes.

vr_reg holds one value: once it is full and the sink stops, the source must wait. When a source makes values in bursts, or a sink stops now and then, it helps to have more room in between. A FIFO (first in, first out) holds several values and hands them on in the order they came.

A ring of places

fifo (Listing 1) keeps its values in a small memory, mem, used as a ring. wr is the place the next value goes, and rd the place of the oldest. Each moves on one place when a value goes in or comes out, and after the last place it wraps back to the first by itself, as a counter does. count is the number of values held.

ABITS, a parameter, sets the size: the FIFO has 2**ABITS places, 2 to the power ABITS. FULL (line 19) is that number, a 1 followed by ABITS zeros in binary: the count when every place holds a value.

Both sides use valid and ready (lesson 10.1). in_ready is 1 while there is room, and out_valid while a value waits; the oldest value is always on out_data, so the sink sees it at once. A value can go in and another come out at the same edge, and count then stays as it was. Both flags follow count, a register, so they change only at rising edges: a full FIFO has room again only after the edge where a value leaves.

How many places

A FIFO evens out bursts; it cannot make a slow sink faster. It needs as many places as the values that pile up while the sink falls behind. If values keep coming faster than they leave, any FIFO fills, and from then on the source waits.

fifo reads mem with no clock edge, so Vivado builds it from distributed RAM (lesson 6.3).

Question 3 of 3. Find the bug

fifo_bug should keep count equal to the number of values it holds, as fifo does. Its testbench, the one fifo passes, fails at the first edge where a value goes in and another comes out: afterwards count is 4, with 3 values held. Pick the line that is wrong.

Show answer and explanation

The bug is on line 47, if (push) count <= count + 1'b1;. It should read if (push & ~pop) count <= count + 1'b1;.

At an edge where one value goes in and another comes out, the count must stay put. if (push) adds 1 whenever a value goes in, whether or not one also leaves. So count gains 1 at every such edge: the FIFO soon turns values away with a place free, and later says a value waits when it is empty, handing the sink an old one.
