10.1 Valid and ready

Teaches Valid/ready handshake (primitive). About 6 minutes.

Inside a design, one part often makes values that another uses: a receiver hands bytes to a buffer, a buffer to a transmitter. Sometimes the first has nothing to give, sometimes the second is busy. Two signals let them agree, cycle by cycle, without either knowing how the other works.

Valid and ready

The part that gives is the source, the part that takes the sink. The source drives data and valid: 1 means a value is on data now. The sink drives ready: 1 means it can take a value now. A value moves at a rising edge where valid and ready are both 1 just before it; at every other edge, nothing moves. Three rules keep this safe:

  • Once the source sets valid to 1, it holds valid and data still until the value has moved. It cannot take an offer back.
  • The sink may change ready whenever it likes, and may wait to see valid first.
  • The source must never wait for ready before setting valid: if each waited for the other, nothing would ever move.

A sink that sets ready to 0 holds the source back: backpressure. Valid and ready are a handshake, like lesson 9.3's request and answer, but on one clock, so neither needs a synchroniser. These are the rules of AXI4-Stream, the streaming interface of many of AMD's IP, the ready-made blocks it supplies for its FPGAs, where the signals are called TVALID and TREADY.

One register between them

vr_reg (Listing 1) holds one value between a source and a sink. To the source it is a sink, to the sink a source. It has room for a new value when it is empty, or when its value leaves at the same edge.

Questions

Question 1 of 3. Predict out_valid

This is lesson 10.1's vr_reg, a register of one place, empty at the start, between a source and a sink. A value moves at a rising edge where its valid and its ready are both 1 just before it. Cycles 0 and 1 are drawn for you. Set out_valid for the rest.

Question 2 of 3. Predict out_valid

vr_reg, lesson 10.1's register of one place, empty at the start. in_ready is not drawn: it is 1 when the register is empty or its value leaves at the same edge. Set out_valid for every cycle.

Question 3 of 3. Find the bug

vr_reg_bug should pass every value from its source to its sink once, in order, as lesson 10.1's vr_reg does. Its testbench, the one vr_reg passes, fails: where the sink should get 3, it gets 4. Pick the line that is wrong.

Show answer and explanation

The bug is on line 26, if (in_valid) out_data <= in_data;. It should read if (in_valid & in_ready) out_data <= in_data;.

out_data must change only when a value moves in: at an edge where in_valid and in_ready are both 1. As written it takes in_data whenever in_valid is 1. While the register holds 3 and the sink is not ready, in_ready is 0 and the source waits with 4, but the register takes 4 anyway. 3 is lost, and 4 comes out twice.
