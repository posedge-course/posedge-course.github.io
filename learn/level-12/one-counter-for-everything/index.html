12.3 One counter for everything

Teaches Loop counter (circuit). About 6 minutes.

The 3D decoder has one engine for each layer, and all four work at once, each on a different voxel. An engine reuses a small block of arithmetic, a tile, over the kernel's taps and the channels. A hidden engine's tile is 16 lanes like lesson 12.1's, one for each output channel: it takes 8 input channels and makes 16 output channels at once, so its 128 inputs come in 16 input groups and its 128 outputs in 8 output groups.

Three loops, one count

For one voxel, a hidden engine works through each output group; within it, each of the kernel's 27 taps; within each tap, each input group, one cycle each. That is 27 × 16 × 8 = 3,456 cycles: the decoder's slot.

One counter runs all three loops. The input group moves on every cycle, the tap when the input group wraps round to 0, and the output group when the tap does, like the digits of a counter. The weights are stored in the order they are used, so the count itself is the weight memory's address.

An output group's 16 sums gather every tap and input group. So they start from their biases where the tap and the input group are both 0, and they are finished where both are at their last.

One slot for all

In the first design, all four engines start their next voxels together, once a slot. The hidden engines set its length; the first engine needs only 432 cycles a voxel and the last 459, so they spend most of each slot waiting. The thesis's later builds drop the shared slot: an engine starts its next voxel once the voxels it reads are written, as level 11's layers do, and a pass falls from 556,879 cycles to 427,475.

nest_count (Listing 1) is that counter for small loops: NOG output groups, T taps and NIG input groups. It keeps the loops as the digits og, tap and ig; waddr, the weight address, counts beside them, the same count in plain binary. first and last mark where each sum starts and ends.

Questions

Question 1 of 3. Predict first

Lesson 12.3's nest_count with NOG = 3 output groups, T = 2 taps and NIG = 2 input groups; og, tap and ig are drawn. first is 1 in each cycle that starts a new sum, from the bias. Cycles 0 and 1 are drawn for you. Set first for the rest.

Question 2 of 3. Predict last

Lesson 12.3's nest_count with NOG = 2, T = 2 and NIG = 3. Only busy and the weight address waddr are drawn. last is 1 in each cycle that completes a sum. Set last for every cycle.

Question 3 of 3. Find the bug

nest_count_bug should start one sum for each output group, as lesson 12.3's nest_count does. Its testbench fails where og is 0, tap 1 and ig 0: first is 1 there, where it should be 0. Pick the line that is wrong.

Show answer and explanation

The bug is on line 23, assign first = busy & (ig == 2'd0);. It should read assign first = busy & (tap == 2'd0) & (ig == 2'd0);.

ig is 0 at the start of every tap, so this first would load the bias again at each tap and throw away the products gathered so far. A sum starts only where tap and ig are both 0: once for each output group.
