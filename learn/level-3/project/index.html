Level 3

Level 3 project Write a testbench that catches a planted bug

Write my_reg_en_tb.sv so that it prints TEST PASSED with reg_en and TEST FAILED with reg_en_planted, then say from its waveform what the planted bug does. About 45 minutes in simulation.

In levels 1 and 2, a testbench you did not write told you whether your design was right. Now you write the testbench, and two designs tell you whether it is right. One is lesson 2.4's register, reg_en. The other, reg_en_planted, is a copy with one planted bug. A good testbench passes the first and fails the second. You need only Icarus Verilog and the waveform viewer from level 0's project. The board steps at the end are optional.

The design under test

Both designs have these ports. reg_en_planted.sv says in its first lines what it should do, which is what reg_en does; the last column is where each port goes on the board.

PortDirection and widthWhat it doesOn the board
clkinput, 1 bitthe clockthe 100 MHz oscillator
rstinput, 1 bitat a rising edge where it is 1, q becomes 0button BTN0, pressed is 1
loadinput, 1 bitat a rising edge where it is 1, and rst is 0, q takes dbutton BTN1, pressed is 1
dinput, 4 bitsthe value to loadswitches SW0 (bit 0) to SW3
qoutput, 4 bitsthe value heldLEDs LD4 (bit 0) to LD7

You write my_reg_en_tb.sv. No file you save from this page has that name, so saving the course's answer later never overwrites your work. Each of the two designs keeps its own module name, so both files can sit in one folder.

Two runs

iverilog needs your testbench and the one design it uses; you change only the instance line between the two runs. -g2012 turns on SystemVerilog, which these files use.

With reg_en in your instance line:

iverilog -g2012 -o good_sim my_reg_en_tb.sv reg_en.sv, then vvp good_sim

With reg_en_planted in your instance line:

iverilog -g2012 -o planted_sim my_reg_en_tb.sv reg_en_planted.sv, then vvp planted_sim

What you see when it works

  • With reg_en: TEST PASSED.
  • With reg_en_planted: one or more TEST FAILED lines, the first just after a rising edge where rst and load were both 1. A testbench written from these steps printed TEST FAILED: q=5, expected 0 at 60 ns; yours will show its own values and times.
  • In the waveform, at that rising edge: rst is 1, load is 1, and q takes d while expected becomes 0.

If it fails

These are the messages Icarus Verilog 13 prints for the usual mistakes; version 12 prints the same. Other versions may word them a little differently.

  • syntax error, or a line ending requires SystemVerilog.: the command lacks -g2012. Add it.
  • Unknown module type: reg_en: the command names only your testbench. Add the design file. If the name after "type:" is not one of the two designs, your instance line has a typo.
  • With reg_en, the first line is TEST FAILED: q=x, expected 0 at 10 ns: the register has not been reset yet, so the simulator shows its value as X (lesson 3.2), while your model already says 0. Make the first row a reset, so both start from a value the code states.
  • With reg_en, a line like TEST FAILED: q=0, expected 5 at 60 ns: your model lets load win over rst. Lesson 2.4's register tests rst first.
  • With reg_en_planted, TEST PASSED: your inputs never try rst and load together. See the step about choosing the inputs.
  • vvp prints its verdict but never ends, and my_reg_en_tb.vcd keeps growing: your testbench has no $finish, so its clock runs for ever (lesson 3.1). Press Ctrl+C, then type finish at the > prompt that vvp shows. Delete the waveform file, add $finish after the verdict, and run again.
  • The terminal cannot find iverilog: as in level 0's project, the install did not put it on your path.

On the board (optional)

You need an Arty A7 and Vivado for this part. Everything above works without them.

The board steps use Vivado's project mode, as in levels 1 and 2. Only the design is built; your testbench never is (lesson 3.4).

Your checklist

Simulation path

  1. Write down lesson 2.4's rules for reg_en, one line each. At a rising edge: if rst is 1, q becomes 0, whatever load is; otherwise, if load is 1, q takes d; otherwise q keeps its value.
  2. Make a new folder and save reg_en.sv and reg_en_planted.sv into it from the list above. Do not read reg_en_planted.sv yet: let your testbench find its bug.
  3. In the same folder, make a file my_reg_en_tb.sv that starts with `timescale 1ns/1ps, as lesson 3.1's testbench does, so that its delays are in nanoseconds; then a module my_reg_en_tb with no ports. Declare clk, rst and load, the 4-bit d and q, and an instance of reg_en joined to them by name (lesson 3.1). Make a 10 ns clock, record the waveform into my_reg_en_tb.vcd, and wait for the first rising edge before anything else.
  4. Add a model: a 4-bit expected that follows your rules at every rising edge, written the simplest way you can trust (lesson 3.3).
  5. At every falling edge, compare q with expected using !==; if they differ, print TEST FAILED with the time and add 1 to an error count. Then set the inputs for the next rising edge. At the end, print TEST PASSED only if the count is 0, then $finish.
  6. Choose the inputs so that every line of your rules is tried: a reset with load at 0, a reset with load at 1, a load of a new d, and a cycle with load at 0 while d changes. Start with a reset.
  7. Run iverilog -g2012 -o good_sim my_reg_en_tb.sv reg_en.sv, then vvp good_sim. It must print TEST PASSED: a testbench that fails a correct design is wrong, so fix the testbench first.
  8. In your instance line, change reg_en to reg_en_planted. Run iverilog -g2012 -o planted_sim my_reg_en_tb.sv reg_en_planted.sv, then vvp planted_sim. It must print TEST FAILED.
  9. Open my_reg_en_tb.vcd in the viewer at the time of the first TEST FAILED line, and look at the rising edge before it. Write one sentence saying what the planted design did wrong there. Then open reg_en_planted.sv and find the line.
  10. Open the course's testbench at the bottom of this page. It uses reg_en_planted; with reg_en in its instance line, it prints TEST PASSED. Did yours try rst and load together? Would it still catch the bug if that row were left out?

On the board (optional)

  1. In Vivado, create an RTL project for the part xc7a100tcsg324-1 (on an Arty A7-35T, xc7a35ticsg324-1L), as in level 1's project. Add reg_en_planted.sv as a design source and the saved reg_en_planted.xdc as a constraints file. Your testbench stays out: it is never built.
  2. Run Generate Bitstream, then program the board as in level 2's project.
  3. Set some switches and press BTN1: LD4 to LD7 copy them. Press BTN0 alone: they go off. Load again, then hold BTN1 and press BTN0 as well. Lesson 2.4's register would go off, because the reset wins. Watch what this one does, and compare it with your sentence from the explain step.
