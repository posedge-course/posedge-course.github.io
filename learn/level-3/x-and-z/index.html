3.2 Reading waveforms: X and Z

Teaches X (unknown) (primitive), Z (not driven) (primitive). About 6 minutes.

Inside the FPGA, every signal is 0 or 1. A simulator has two more: X, for a value it cannot know, and Z, for a wire that nothing drives.

Listing 1 holds one bit, q, like lesson 2.4's register without its reset, and puts it on a pin only while oe, its output enable, is 1. Figure 1 is its simulation.

X: unknown

q has no reset, so until its first load the code never says what it holds. The simulator shows X, unknown, drawn hatched. On the board, q starts at 0, as every flip-flop so far does when the FPGA loads its bitstream (lesson 2.3). X does not mean the hardware is in a strange state; it means the code never said.

X spreads: anything worked out from an X is X, unless another input already decides the result. X & 0 is 0 and X | 1 is 1, whatever X is, but X & 1 is X. A testbench signal that nothing ever sets is X too.

Z: not driven

While oe is 0, oe ? q : 1'bz gives 1'bz: the module lets go of pin, and nothing drives it. The simulator shows Z, short for high impedance, drawn on the half-way line. Logic that reads a Z cannot tell its value either, so it works it out as if it were X.

Inside an FPGA every wire has a driver, so only a pin can really let go. Vivado builds Listing 1 with a tri-state buffer at the pin, an OBUFT: an output buffer that can stop driving.

What each points at

When you see X, look for a register with no start value, a signal nobody set, or a bit that does not exist, such as bit 4 of a four-bit sum (level 1's project). When you see Z, look for a port nobody connected or an output that let go.

A bus, a vector drawn as one lane, is still drawn in hexadecimal (lesson 1.1), but if any of its bits is X the whole bus is drawn as X, and the same goes for Z.

Questions

Question 1 of 4. Predict q

X is drawn hatched. This is a second copy of lesson 3.2's pin_hold, with its own inputs: at a rising edge where load is 1, q takes d; otherwise it keeps its value. q has no reset, so until its first load the simulator shows X. Cycles 0 and 1 are drawn for you. Set q for the rest: 0, 1 or X.

Question 2 of 4. Predict siren

This is lesson 0.2's alarm: siren is armed & opening, and opening is door_open | window_open. The testbench leaves armed at X, as if nothing had set it. Set siren for each step: 0, 1 or X.

Question 3 of 4. Fill the blank

While oe is 0, pin must be let go: nothing may drive it. Type the value that does that.

hdl/level-03/pin_hold/pin_hold.sv

1// Holds one bit and puts it on a pin only while oe (output enable) is 1.
2// q has no reset, so the code never says what it starts at.
3// While oe is 0, the module lets go of the pin: nothing drives it.
4module pin_hold (
5 input logic clk,
6 input logic load, // at a rising edge, q takes d when load is 1
7 input logic d,
8 input logic oe, // output enable
9 output logic pin
10);
11 logic q;
12
13 always_ff @(posedge clk) begin
14 if (load) q <= d;
15 end
16
17 assign pin = oe ? q : (blank);
18endmodule
Show answer and explanation

The blank is 1'bz. Also accepted: 1'hz, 1'oz, 1'dz, 'z.

1'bz is one bit of Z, not driven. While oe is 0 the conditional gives it, so the module lets go of pin; Vivado builds this as an OBUFT at the pin (lesson 3.2). 1'b0 would drive the pin low, which is not the same as letting go.

Question 4 of 4. Find the bug

At a rising edge, rst should clear all four bits of q; otherwise q takes d. The testbench fails, and the waveform shows q as X after the first reset. Pick the line that is wrong.

hdl/level-03/reg4_bug/reg4_bug.sv

  • 1// A 4-bit register with a synchronous reset: at a rising edge, rst clears
  • 2// all four bits of q; otherwise q takes d.
  • 3module reg4_bug (
  • 4 input logic clk,
  • 5 input logic rst,
  • 6 input logic [3:0] d,
  • 7 output logic [3:0] q
  • 8);
  • 9 always_ff @(posedge clk) begin
  • 10 if (rst) q[1:0] <= 2'b00;
  • 11 else q <= d;
  • 12 end
  • 13endmodule
Show answer and explanation

The bug is on line 10, if (rst) q[1:0] <= 2'b00;. It should read if (rst) q <= 4'b0000;.

q[1:0] <= 2'b00; gives a value only to bits 1 and 0 (a part-select, lesson 1.1). Bits 3 and 2 get none at the first reset, so they stay X (lesson 3.2), and after a later reset they keep whatever they held. The first failure is q=xx00, expected 0000 at 10 ns. Written if (rst) q <= 4'b0000;, the reset clears all four bits. The else line is right: it loads all four.
