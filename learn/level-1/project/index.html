Level 1

Level 1 project Add the switches and the buttons

Write switch_adder in my_switch_adder.sv until the provided testbench prints TEST PASSED for all 256 sums, then read the sums in its waveform. About 40 minutes in simulation.

In this project you write a module from a description for the first time, and a testbench you did not write tells you whether it is right. You need only Icarus Verilog and the waveform viewer from level 0's project; if you skipped it, its first steps install them. The board steps at the end are optional.

The module

The module is called switch_adder. It adds the number on four switches to the number on four buttons, like lesson 1.1's adder, and has one output of its own, big, which no lesson shows. These are its five ports; the last column is where each one goes on the board.

PortDirection and widthWhat it isOn the board
ainput, 4 bitsthe first numberswitches SW0 (bit 0) to SW3
binput, 4 bitsthe second numberbuttons BTN0 (bit 0) to BTN3, pressed is 1
lowoutput, 4 bitsthe four low bits of the sumLEDs LD4 (bit 0) to LD7
carryoutput, 1 bit1 when the sum is more than 15RGB LED LD0, green
bigoutput, 1 bit1 when the sum is more than 9RGB LED LD1, blue

You write it in a file named my_switch_adder.sv. The course's own answer, which you can open after the checklist, has another file name, so saving it later never overwrites your work.

Two commands

The first command compiles the testbench together with your file. -g2012 turns on SystemVerilog, which both files use. It prints nothing when it works:

iverilog -g2012 -o switch_adder_sim switch_adder_tb.sv my_switch_adder.sv

The second runs the simulation. The testbench checks low, carry and big for eight chosen sums and then for every pair of a and b, and writes the waveform file:

vvp switch_adder_sim

What you see when it works

The terminal prints TEST PASSED. Figure 1 shows the first eight steps of the waveform: the sums are 7, 17, 10, 9, 15, 30, 9 and 0; carry is 1 at 10 ns and 50 ns, and big is 1 at 10, 20, 40 and 50 ns.

If it fails

These are the messages Icarus Verilog 13 prints for the usual mistakes; version 12 prints the same, except where a line says otherwise. Other versions may word them a little differently.

  • syntax error, or a line ending requires SystemVerilog.: the command lacks -g2012. Add it.
  • Unknown module type: switch_adder: the command names only the testbench, or the module in your file has another name. The file is my_switch_adder.sv, but the module in it must be called switch_adder.
  • Every step fails, and every line shows carry=x: sum is too narrow, so sum[4] does not exist (lesson 1.1). x is how the simulator prints a value it cannot know; level 3 says more.
  • The first line shows big=x, and later lines show big=1 for sums of 9 or less, such as TEST FAILED: 9+0: low=9 carry=0 big=1 at 40 ns (the time is the end of the step, as in lesson 0.4): some path through your always_comb block gives big no value, so it keeps its old one. That is a latch (lesson 1.4). Give big a value on every path.
  • TEST FAILED: 9+8: low=1 carry=1 big=0 at 20 ns, and big=0 for every sum of 16 or more: your comparison adds a and b again, in four bits, so it loses the carry (lesson 1.1). Compare sum, the five-bit total.
  • sorry: constant selects in always_* processes are not fully supported (version 12: are not currently supported (all bits will be included)): you read part of sum inside always_comb. The simulation still gives the right results, but this course keeps selects in assign lines, as lesson 1.1 does, where Icarus prints nothing.
  • warning: A non-blocking assignment should not be used in an always_comb process.: a line in your block uses <=. Inside always_comb, assign with = (lesson 1.3).
  • The terminal cannot find iverilog: as in level 0's project, the install did not put it on your path.

On the board

Vivado takes an hour or more to install and needs tens of gigabytes of disk, so the board steps are for when you have the time. They use Vivado's project mode, where you click through the same build this course runs as a script.

Listing 1 is the start of the Slice Logic table from the course's build of its answer. A slice is one of the small groups of LUTs and flip-flops the chip is built from. Slice Registers counts the cells that remember a value, and the Register as Latch row below it is where a latch would be counted. Your build should agree on those rows. Its LUT count can differ, because Vivado may build your lines another way.

Your checklist

Simulation path

  1. Make a new folder and save switch_adder_tb.sv into it from the list above. It is the specification: it checks all three outputs for every pair of a and b.
  2. In the same folder, make a file my_switch_adder.sv. In it, write a module named switch_adder, the name the testbench uses, with the five ports in the table above. Give low and carry their values as lesson 1.1 does.
  3. Give big the value 1 when the sum is more than 9, and 0 when it is not, in an always_comb block with an if (lesson 1.3). > compares two numbers as == does (lesson 1.4), and is 1 when the left one is larger. Every path through the block must give big a value (lesson 1.4).
  4. Open a terminal in the folder and run iverilog -g2012 -o switch_adder_sim switch_adder_tb.sv my_switch_adder.sv. It prints nothing when it works.
  5. Run vvp switch_adder_sim. Change your file and run both commands again until it prints TEST PASSED.
  6. Open switch_adder_tb.vcd in the viewer and add a, b, low, carry and big from switch_adder_tb. At 10 ns, a is 9 and b is 8: low is 1 and carry is 1, so the sum is 16 + 1 = 17. At 50 ns both are F: low is E and carry is 1, so the sum is 16 + 14 = 30.
  7. Look at big at 20 ns, 30 ns and 60 ns, where the sums are 10, 9 and 9. It is 1 only at 20 ns: 9 is not more than 9.

On the board (optional)

  1. Install Vivado ML Standard, AMD's free edition, on Windows or Linux, with only the Artix-7 devices selected. Download the installer from AMD's website, which asks you to sign in with a free AMD account; UG973 (under "Further reading") describes each step. It is a large download. Vivado does not run on macOS; on a Mac, the simulation steps are the whole project.
  2. In Vivado, create an RTL project for the part xc7a100tcsg324-1 (on an Arty A7-35T, xc7a35ticsg324-1L). Add your my_switch_adder.sv as a design source and the saved switch_adder.xdc as a constraints file.
  3. Run Generate Bitstream and wait until Vivado says it has finished. It runs synthesis and place and route first (lesson 0.3).
  4. Connect the board by USB. Open the Hardware Manager, then Open Target, Auto Connect and Program Device.
  5. With no button pressed, b is 0, so LD4 to LD7 show the switches. Move SW0 alone and watch LD4: the position that lights it is 1 on your board.
  6. Set the switches to 9: SW3 and SW0 at 1, SW2 and SW1 at 0. Hold BTN3, which adds 8. LD4 lights and LD5 to LD7 stay off, LD0 lights green and LD1 lights blue: 17 is 16 + 1, and more than 9. The RGB LEDs are very bright when held at 1, so do not look straight into them; level 4's project dims an LED.
  7. In the Flow Navigator, under Implementation, click Open Implemented Design, then Report Utilization, and click OK. Find the Slice Logic table in the report that opens, and compare it with Listing 1 on this page, from the course's build of its own answer.
