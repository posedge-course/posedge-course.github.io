1.3 Multiplexers with ?:, if and case

Teaches Multiplexer (primitive), always_comb (primitive). About 5 minutes.

Logic's other everyday job is choosing. A multiplexer passes one of its inputs to its output, and a select signal says which. With two inputs a and b and a select sel, the output y is b when sel is 1 and a when sel is 0. SystemVerilog gives you three ways to write that.

Three spellings

The conditional operator fits on one line: the condition, then ?, then the value for 1, then :, then the value for 0.

The other two spellings sit inside an always_comb block, which describes combinational logic: outputs worked out from the inputs as they are now, with no memory, using statements such as if. The block is worked out again whenever one of its inputs changes. Inside it you assign with =; <= is for flip-flops, which level 2 explains. With if and else, the choice reads like Listing 1.

For more than two inputs, case runs the line whose value matches sel. Listing 2 is a 4-to-1 multiplexer: sel picks which of d0 to d3 reaches y.

2'd1 is a sized number: 2 bits wide, written in decimal, value 1. With 'b you write the bits in binary instead, so 4'b0110 is 6. default covers every value of sel that no line lists. Always write one; lesson 1.4 shows why.

One circuit

Synthesis builds the same circuit from all three spellings: the 2-to-1 multiplexer is one LUT3 whether you write the conditional operator, if or case. mux4 has six inputs, four data bits and two select bits, so it is exactly one LUT6 (Figure 1). Each output bit of a multiplexer costs one LUT, as long as it depends on six inputs or fewer.

Questions

Question 1 of 4. Predict y

The testbench joins bit 0 of its vector d to d0, bit 1 to d1, and so on. Here d stays at 6, which is 0110: d3 is 0, d2 is 1, d1 is 1 and d0 is 0. sel picks which of them reaches y. Steps 0 and 1 are drawn for you. Set y for the rest.

Question 2 of 4. Fill the blank

y must be b when sel is 1 and a when sel is 0. Type what goes after the question mark.

hdl/level-01/mux2/mux2.sv

1// A 2-to-1 multiplexer: y is b when sel is 1, and a when sel is 0.
2module mux2 (
3 input logic sel,
4 input logic a,
5 input logic b,
6 output logic y
7);
8 assign y = sel ? (blank);
9endmodule
Show answer and explanation

The blank is b : a. Also accepted: b: a, b :a, b:a.

The conditional operator gives the value before : when the condition is 1, and the value after it when the condition is 0. So b comes first. Written the other way round, the multiplexer would pass the wrong input for both values of sel.

How many cells that remember a value did Vivado use for mux4?

Show answer and explanation

The report says 0.

Read the Used column of the Slice Registers row. always_comb describes logic, worked out from the inputs as they are now, and every path through mux4's block gives y a value, so nothing has to remember anything: the multiplexer is a LUT and nothing else. Lesson 1.4 shows how an always_comb block can end up with memory all the same.

Question 4 of 4. Find the bug

In mode 1, these LEDs should show the opposite of the switches, but the testbench fails. Pick the line that is wrong.

hdl/level-01/led_mode_bug/led_mode_bug.sv

  • 1// Four pictures on four LEDs, chosen by mode: mode 0 shows the switches,
  • 2// mode 1 the opposite of the switches, mode 2 all LEDs on, mode 3 all off.
  • 3module led_mode_bug (
  • 4 input logic [1:0] mode,
  • 5 input logic [3:0] sw,
  • 6 output logic [3:0] led
  • 7);
  • 8 always_comb begin
  • 9 case (mode)
  • 10 2'd0: led = sw;
  • 11 2'd1: led = sw;
  • 12 2'd2: led = 4'b1111;
  • 13 default: led = 4'b0000;
  • 14 endcase
  • 15 end
  • 16endmodule
Show answer and explanation

The bug is on line 11, 2'd1: led = sw;. It should read 2'd1: led = ~sw;.

case (mode) runs the line whose label matches, and 2'd1 is mode 1. That line copies sw, exactly like mode 0. The opposite of the switches is ~sw: ~ turns over each of the four bits (lesson 1.2). The testbench's first failure is mode 1 with every switch at 0, where all four LEDs should be on.
