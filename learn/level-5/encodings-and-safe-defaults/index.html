5.3 Encodings and safe defaults

Teaches State encoding (primitive). About 5 minutes.

The state register holds a code for each state. Which code goes with which state is the machine's state encoding.

Binary and one-hot

door2's enum gives its three states the codes 00, 01 and 10. That is a binary encoding: the fewest bits that give every state a code of its own.

A one-hot encoding gives each state a bit of its own, and exactly one bit is 1: four states would be 0001, 0010, 0100 and 1000. It takes more flip-flops, but each state is a single bit, so a question such as "is the door open?" reads one bit instead of comparing a whole code. Listing 1 is door2 with one-hot codes. Its enum is left out here, because the first question below asks for part of it: it gives each state its code with a line such as CLOSED = 3'b001. Each output reads one bit of state.

What Vivado chooses

Vivado recognises a state machine as it reads one, and may choose a new encoding for it. For door2, its log says it found the state machine and gave the states one-hot codes, whatever the enum said. FPGAs have flip-flops to spare, and one-hot often makes the next-state logic smaller. If you need your own codes kept, synthesis can be told to leave state machines alone.

Safe defaults

Two bits hold four codes and three bits hold eight, but the door has only three states. The register should never hold any other code. If it ever does, default in the next-state logic sends the machine to CLOSED at the next edge, instead of leaving it stuck in a code that no line handles: a safe state. Vivado may still drop that way back, since no transition reaches the extra codes; fsm_safe_state, a setting written on the state register, makes it keep one.

Question 1 of 3. Fill the blank

Lesson 5.3's one-hot door gives each state a bit of its own: CLOSED is 3'b001 and OPEN is 3'b010. Type LOCKED's code.

hdl/level-05/door_onehot/door_onehot.sv, lines 12 to 16

12 typedef enum logic [2:0] {
13 CLOSED = 3'b001,
14 OPEN = 3'b010,
15 LOCKED = (blank)
16 } state_t;
Show answer and explanation

The blank is 3'b100. Also accepted: 3'd4, 3'h4, 3'o4.

One-hot means exactly one bit is 1, and each state has a different one. CLOSED has bit 0 and OPEN bit 1, so LOCKED gets bit 2: 3'b100. It is the bit is_locked reads.

The report says 3.

Three: Vivado gave the three states one-hot codes, one flip-flop for each, where the enum's binary codes needed two (lesson 5.3). The LUT6 row, three LUTs, is the logic around them; IBUF and OBUF are the pins and BUFG the clock.

The bug is on line 13, CLOSED = 3'b011,. It should read CLOSED = 3'b001.

CLOSED's code, 3'b011, has two bits set, so it is not one-hot. Bit 1 is OPEN's, so while the door is closed, is_open reads 1. The three codes are still all different, so the transitions work; only the outputs, which read single bits, go wrong. Written 3'b001, CLOSED has a bit of its own.
