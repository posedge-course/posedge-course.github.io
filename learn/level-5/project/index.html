Level 5

Level 5 project A UART transmitter

Write uart_tx in my_uart_tx.sv until uart_tx_tb.sv prints TEST PASSED, then work out how many bits a second it sends at 868 cycles a bit. About 60 minutes in simulation.

A UART sends bytes over a single wire, one bit at a time, and the board's USB port carries them to your computer. This project builds the sending half: a state machine that times each bit, with a counter and a shift register as its datapath. It uses lesson 4.1's counter, 4.3's shift register and every lesson of this level. You need only Icarus Verilog and the waveform viewer. Level 7 puts it on the board.

One byte on one wire

The line rests at 1. A byte goes out as a frame of ten bits, each lasting the same time: a start bit, 0, which tells the receiver a byte is coming; the eight data bits, bit 0 first; and a stop bit, 1, which leaves the line at rest again. Both ends agree on how long a bit lasts. The rate in bits a second is the baud rate, and 115,200 is a common one.

The ports of uart_tx
PortDirection and widthWhat it is
clkinput, 1 bitthe clock
rstinput, 1 bitat a rising edge where it is 1, the transmitter goes idle
sendinput, 1 bita one-cycle pulse that starts sending data; ignored while busy is 1
datainput, 8 bitsthe byte to send, read at the edge that takes send
txoutput, 1 bitthe serial line: 1 at rest, then each frame
busyoutput, 1 bit1 from the edge that takes send until the stop bit has ended

The file you write is my_uart_tx.sv, so saving the course's answer later never overwrites it; the module inside is uart_tx. -g2012 turns on SystemVerilog.

What you see when it works

  • The run prints TEST PASSED: the receiver model read all six bytes, and busy was 1 for every frame and 0 between them.
  • In the waveform, each bit of the first frame lasts 5 cycles, and the data bits of 41 read 1, 0, 0, 0, 0, 0, 1, 0 from bit 0: 0100_0001 written from bit 7.
  • The working-out: a bit lasts LAST + 1 = 868 cycles of 10 ns, which is 8.68 µs, so 100,000,000 / 868 = about 115,207 bits go out in a second: 115,200 baud, to within 0.01%. A frame of ten bits takes 86.8 µs.

If it fails

  • syntax error, followed by Invalid module instantiation: the command lacks -g2012. Add it.
  • Unknown module type: uart_tx: the command does not name my_uart_tx.sv, or the module in it has another name. It must be called uart_tx.
  • TEST FAILED: stop bit is 0 at 530 ns, then received 03, expected 41: the bits last too long. Check that the timer goes back to 0 after LAST, not only while idle.
  • TEST FAILED: received 82, expected 41 at 530 ns: the bits go out in the wrong order, bit 7 first. Send bit 0 first and shift the register down.
  • TEST FAILED: busy=0 during a frame at 60 ns: busy is 0 in part of the frame. It must be 1 in every state but IDLE.
  • TEST FAILED: busy=0 during a frame at 510 ns, near the end of the first frame: the stop bit is missing. DATA must go to STOP, not straight to IDLE.
  • TEST FAILED: received fc, expected 3c: a send in the middle of a frame reloaded the shift register. Load it only while idle.
  • The terminal cannot find iverilog: as in level 0's project, the install did not put it on your path.

These messages are from Icarus Verilog 12.

Your checklist

Simulation path

  1. Make a new folder and save uart_tx_tb.sv into it from the list above. It is the specification: it sets LAST to 4, so each bit lasts 5 cycles, and a receiver model inside it reads every byte from tx and checks it.
  2. On paper, draw the transmitter's states as lesson 5.1 drew the door's: IDLE, START, DATA and STOP, with an arrow for each transition and the input that takes it: send, the end of a bit, the end of the eighth data bit.
  3. In the same folder, make a file my_uart_tx.sv with a module named uart_tx, the name the testbench uses. Give it the parameters BITS (default 10) and LAST (default 867), and the six ports in the table above.
  4. Add the bit timer: a counter of BITS bits that goes back to 0 while the transmitter is idle and after LAST, and otherwise counts up (lesson 4.1). Make a signal that is 1 in a bit's last cycle, when the timer equals LAST.
  5. Add the controller in the two-block form (lesson 5.2), with the four states as an enum: IDLE goes to START on send; START to DATA at the end of a bit; DATA to STOP at the end of the eighth bit; STOP to IDLE at the end of a bit.
  6. Add the datapath (lesson 5.4): when send comes while idle, load data into an 8-bit shift register and set a 3-bit bit count to 0. At the end of each bit in DATA, shift the register down one place, with a concatenation as in lesson 4.3 but with a 0 coming in at the top, and add 1 to the count.
  7. Make tx 0 in START, bit 0 of the shift register in DATA, and 1 in every other state. Make busy 1 in every state but IDLE.
  8. Run iverilog -g2012 -o uart_sim uart_tx_tb.sv my_uart_tx.sv, then vvp uart_sim. Change your file and run both again until it prints TEST PASSED.
  9. Open uart_tx_tb.vcd and add send, data, tx and busy from uart_tx_tb. Find the first byte, 41 in hexadecimal, the letter A. Mark each 5-cycle bit and read the eight data bits, bit 0 first.
  10. With the default LAST, 867, on a 100 MHz clock, work out how long one bit lasts, how many bits go out in a second, and how long one byte takes. Then compare with "What you see when it works" above.
