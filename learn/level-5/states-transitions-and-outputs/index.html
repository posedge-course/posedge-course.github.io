5.1 States, transitions and outputs

Teaches State machine (circuit). About 5 minutes.

A counter remembers a number. Many designs must remember something else: where they are in a sequence. A door is closed, open or locked, and what a push does depends on which. A state machine keeps that in a register, the state register, and moves from one state to another at clock edges.

Figure 1 draws the door's state machine: a circle for each state, and an arrow for each transition, labelled with the input that takes it.

Listing 1 is the same door in SystemVerilog.

Naming the states

The typedef enum line declares an enumerated type, state_t: a type whose values have names. CLOSED, OPEN and LOCKED stand for 0, 1 and 2, in the order they are listed, held in two bits. state is the state register. Code reads the names, and a waveform shows the numbers.

Transitions

At each rising edge, case (state) runs the line for the state the door is in, and its if decides where to go. A closed door opens on push and locks on key; push is tested first, so it wins if both come at once. An open door ignores key, and a locked one ignores push. Where no line gives state a value, the register keeps its value, as lesson 2.4's did: the door stays where it is. The reset puts it in CLOSED, and so does default, for any other code (lesson 5.3 says why that matters).

Outputs

is_open and is_locked depend only on state. So they change at the edge where the state changes, and never between edges, whatever the inputs do. Figure 2 shows it.

Questions

Question 1 of 3. Predict is_open

This is lesson 5.1's door, closed at the start. push opens a closed door and closes an open one; key locks a closed door and unlocks a locked one. An open door ignores key, and a locked one ignores push. Cycles 0 and 1 are drawn for you. Set is_open for the rest.

Question 2 of 3. Predict is_locked

Lesson 5.1's door, locked at the start of the window. push opens a closed door and closes an open one; key locks a closed door and unlocks a locked one; if both come to a closed door, push wins. push and key sometimes come together. Set is_locked for every cycle.

Question 3 of 3. Find the bug

This door should work like lesson 5.1's: push opens a closed door and closes an open one, and key locks a closed door and unlocks a locked one. Its testbench fails. Pick the line that is wrong.

  • 2// one; key locks a closed door and unlocks a locked one. An open door
  • 3// cannot be locked, and a locked door does not open. push and key are
  • 4// one-cycle pulses; if both come at once to a closed door, push wins.
  • 5module door_bug (
  • 6 input logic clk,
  • 7 input logic rst, // at a rising edge: the door is closed
  • 8 input logic push,
  • 9 input logic key,
  • 10 output logic is_open,

  • 12);
  • 13 typedef enum logic [1:0] {CLOSED, OPEN, LOCKED} state_t;

  • 16 always_ff @(posedge clk) begin

  • 18 else begin
  • 19 case (state)
  • 20 CLOSED: if (push) state <= OPEN;
  • 21 else if (key) state <= LOCKED;
  • 22 OPEN: if (push) state <= LOCKED;
  • 23 LOCKED: if (key) state <= CLOSED;
  • 24 default: state <= CLOSED;
  • 25 endcase
  • 26 end
  • 27 end

  • 30 assign is_locked = (state == LOCKED);

Show answer and explanation

The bug is on line 22, OPEN: if (push) state <= LOCKED;. It should read OPEN: if (push) state <= CLOSED;.

The OPEN line sends a pushed open door to LOCKED instead of CLOSED, so closing the door locks it. The CLOSED line's second transition also ends in LOCKED, but that one is right: key should lock a closed door. Compare each line with the arrow it stands for in lesson 5.1's Figure 1.
