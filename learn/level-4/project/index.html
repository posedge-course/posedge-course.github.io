Level 4

Level 4 project Dim an LED with two buttons

Write pwm in my_pwm.sv and dimmer in my_dimmer.sv until both provided testbenches print TEST PASSED, then work out how often the board's LED switches on and off. About 60 minutes in simulation.

This project makes an LED dimmer: one button makes the LED brighter, another dims it. It uses every lesson of this level: a counter (4.1), an enable that acts once per press (4.2), an edge detector (4.3) and a debouncer (4.4). You need only Icarus Verilog and the waveform viewer from level 0's project. The board steps are optional.

Dimming by switching

An LED on a pin is either on or off. Switch it on for part of every short period, faster than the eye can follow, and it gives that part of the light: on for a quarter of the time, a quarter of the light. This is pulse-width modulation, PWM, and the part of the period it is on is the duty cycle.

pwm makes the pattern. A counter runs round and round, and out is 1 while the count is less than duty. < compares two numbers, as > did in level 1's project, and is 1 when the left one is smaller. So out is 1 for duty cycles in every period.

The ports of pwm
PortDirection and widthWhat it is
clkinput, 1 bitthe clock
rstinput, 1 bitat a rising edge where it is 1, the count becomes 0
dutyinput, BITS bitshow many cycles of each period out is 1
outoutput, 1 bit1 while the count is less than duty

The dimmer

dimmer holds the brightness in an 8-bit duty, which moves in steps of 32: from 0, off, up to 224, on for 224 cycles in every 256. Each button goes through press, so every press is one pulse, one cycle long, however long it bounces or is held. That pulse is the enable of duty, as a tick is in lesson 4.2.

dimmer_tb.sv sets HOLD to 2, so a press takes a few cycles instead of 10 ms. It presses the buttons with bounces, and after each press counts the cycles in which led is 1 over one whole period of 256.

The files you write are my_pwm.sv and my_dimmer.sv, so saving the course's answers later never overwrites them. Each holds the module the testbench names: pwm and dimmer. -g2012 turns on SystemVerilog, which these files use.

What you see when it works

  • Both runs print TEST PASSED.
  • In pwm_tb.vcd, out is 1 for 2 cycles in every 8 while duty is 2, for 5 while it is 5, and never while it is 0.
  • The working-out: with BITS at 8, a period is 256 cycles of 10 ns, which is 2.56 µs, so led goes on and off about 390,000 times a second. That is far too fast to see: the LED looks steady, and dimmer the smaller duty is.
  • With the board, LD4 has eight settings, from off up to 224 of every 256 cycles, and each press of a button moves it one step.

If it fails

  • syntax error, followed by Invalid module instantiation: the command lacks -g2012. Add it.
  • Unknown module type: pwm: the command does not name my_pwm.sv, or the module in it has another name. The file is my_pwm.sv, but the module must be called pwm. The same goes for dimmer.
  • parameter `BITS` not found: your module has no parameter called BITS; for dimmer, the same for HOLD.
  • TEST FAILED: duty=0 out=x, expected 0 at 10 ns: your count never gets a first value. Check that the rst line sets it to 0.
  • TEST FAILED: duty=0 out=1, expected 0 at 10 ns: out is 1 while the count equals duty, too. It must be less.
  • TEST FAILED: led was 1 for 0 of 256 cycles, expected 32: the presses never reach duty. Check that your press instances pass BITS and HOLD on: with the default HOLD, a press would take a million cycles.
  • TEST FAILED: led was 1 for 224 of 256 cycles, expected 32: one press moved duty more than one step. Use each press pulse, not the button itself.
  • TEST FAILED: led was 1 for 224 of 256 cycles, expected 0, or led was 1 for 32 of 256 cycles, expected 224: duty went past an end and came round from the other. Check the limits at 0 and 224.
  • The terminal cannot find iverilog: as in level 0's project, the install did not put it on your path.

These messages are from Icarus Verilog 12.

Your checklist

Simulation path

  1. Make a new folder and save pwm_tb.sv into it from the list above. It is the specification of pwm: it sets BITS to 3, so a period is 8 cycles, and at every falling edge it checks out against a model.
  2. In the same folder, make a file my_pwm.sv with a module named pwm, the name the testbench uses. Give it a parameter BITS with the default 8 and the four ports in the first table. Inside, write a counter of BITS bits with no terminal count: 0 after a reset, otherwise one more at every rising edge, round and round (lesson 4.1). Then give out the value of count < duty with an assign.
  3. Open a terminal in the folder and run iverilog -g2012 -o pwm_sim pwm_tb.sv my_pwm.sv, then vvp pwm_sim. Change your file and run both again until it prints TEST PASSED.
  4. Open pwm_tb.vcd in the viewer and add duty and out from pwm_tb, and your count from inside dut. While duty is 2, count the cycles in each period with out at 1; do the same where duty is 5 and where it is 0.
  5. Save dimmer_tb.sv, press.sv, debounce.sv and edge_detect.sv into the same folder. press is lesson 4.4's debouncer followed by lesson 4.3's edge detector: one pulse for each press of a button.
  6. Make a file my_dimmer.sv with a module named dimmer, the parameters BITS (default 20) and HOLD (default 999_999), and the five ports in the second table. Make two instances of press, one for each button, passing BITS and HOLD on to them.
  7. Add an 8-bit register duty: 0 after a reset; one step of 32 brighter at an edge where the up pulse is 1 and duty is not already 224; one step dimmer where the down pulse is 1 and duty is not already 0. Then make an instance of your pwm, with BITS 8, that turns duty into led.
  8. Run iverilog -g2012 -o dimmer_sim dimmer_tb.sv my_dimmer.sv my_pwm.sv press.sv debounce.sv edge_detect.sv, then vvp dimmer_sim, until it prints TEST PASSED.
  9. On the board, pwm has BITS 8 and the clock runs at 100 MHz. Work out how long one period of led lasts and how many periods there are in a second. Then compare your answer with "What you see when it works" above.

On the board (optional)

  1. In Vivado, create an RTL project for the part xc7a100tcsg324-1 (on an Arty A7-35T, xc7a35ticsg324-1L), as in level 1's project. Add my_dimmer.sv, my_pwm.sv, press.sv, debounce.sv and edge_detect.sv as design sources and the saved dimmer.xdc as a constraints file. The testbenches stay out: they are never built.
  2. Run Generate Bitstream, then program the board as in level 2's project.
  3. Press BTN3 once: LD4 comes on, dimly. Press it again a few times, then press BTN2 a few times, and watch the steps. Hold BTN3 down: it counts as one press. BTN0 turns the LED off at once.
