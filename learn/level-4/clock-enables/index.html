4.2 Clock enables, not divided clocks

Teaches Clock enable (circuit). About 5 minutes.

The Arty's clock has a rising edge every 10 ns. Many things should happen far less often: an LED that changes once a second, or a display that moves on every few milliseconds.

A clock made from a counter

Bit 1 of a counter goes 0, 0, 1, 1, 0, 0, 1, 1: up and down like a clock four times slower. A slower clock made from a faster one like this is a divided clock. In Figure 1, count counts the cycles of clk, and shown is a register clocked by count[1], so it changes once in every four cycles.

It works in simulation, but it is a trap.

  • The board's clock reaches every flip-flop at almost the same moment. It travels on a clock network, wires built for that, driven by a global clock buffer (BUFG). A divided clock leaves a flip-flop only after clk's edge, so its edges come later, by delays that depend on where the parts are placed.
  • count[1] rises at the moment count changes. The simulator lets count change first, so shown takes the new value. On the board, the old or the new value may arrive first; wire delays decide.
  • Vivado checks that every value arrives in time for the edge that takes it (level 8), but only for clocks it has been told about. Nobody told it about count[1].

Verilator warns too, with SYNCASYNCNET: count is in one block's event list and is read at clk's edges by another.

One clock and an enable

Keep every register on clk, and make a tick instead: a signal that is 1 for one cycle in every N, like lesson 4.1's. A register that changes only at edges where the tick is 1 has it as its enable, which goes to each flip-flop's CE input (lesson 2.4). Figure 1's shown_ce works this way, and like every register on clk, it takes the value from before the edge.

Listing 1 changes an LED once a second.

#(.BITS(BITS), .LAST(LAST)) sets the instance's parameters. An underscore in a number only groups its digits: 99_999_999 is 99,999,999. The tick comes once in every 100,000,000 cycles, one second at 100 MHz, and led changes only at those edges. rst starts both the count and the LED again. Every flip-flop is on clk, so Vivado can check that every value arrives in time.

On the board (optional)

You need an Arty A7 and Vivado for this part. Everything above works without them.

Build tick_led with the pins in Listing 2: BTN0 is rst, and LD4 is led.

After programming, LD4 changes once a second. Hold BTN0 and it goes off and stays off; let go, and it comes on one second later.

BTN0 reaches rst straight from its pin. Let go right at a clock edge, it could release some flip-flops a cycle before others. For an LED that does no harm; lesson 9.4 shows how a design makes its reset safe.

Question 2 of 3. Fill the blank

sampler is the design behind Figure 1's shown_ce in lesson 4.2. Every register in it runs on clk, and take is 1 for one cycle in every four. Type what goes before shown <= count; so that shown loads only at the edges where take is 1.

hdl/level-04/sampler/sampler.sv

1// count counts the cycles of clk. Every four cycles, shown takes a copy
2// of count, for a display to show. take is 1 in the cycles when count
3// ends in 01, and shown loads count at the rising edge that ends each.
4module sampler (
5 input logic clk,
6 input logic rst,
7 output logic [3:0] shown
8);
9 logic [3:0] count;
10 logic take; // the enable for shown
11
12 assign take = (count[1:0] == 2'b01);
13
14 always_ff @(posedge clk) begin
15 if (rst) count <= 4'd0;
16 else count <= count + 1;
17 end
18
19 always_ff @(posedge clk)
20 (blank) shown <= count;
21endmodule
Show answer and explanation

The blank is if (take). Also accepted: if (take == 1'b1), if (take == 1).

if (take) makes take the enable of shown. At an edge where take is 0, no line gives shown a value, so it keeps the one it has (lesson 2.4). The block still runs at every rising edge of clk, like every other register in the design, so nothing needs a clock of its own.
