4.1 Counters

Teaches Counter (circuit). About 5 minutes.

In level 2's project, blink added one to a register at each rising edge while run was 1. A register that adds one like this is a counter. Most designs have several: they count the cycles between two events, step through the addresses of a memory, or count the values that have arrived.

Listing 1 is a counter that stops at a value you choose and starts again.

Parameters

BITS and LAST are parameters, as in level 2's project: constants that each instance of the module can set to its own value (lesson 3.1 met instances). The value after = is the default, used when an instance sets none. A parameter can set a width, as BITS does for count, so the same file makes a 3-bit counter in a testbench and a 27-bit one on the board. int gives BITS its type: a 32-bit whole number.

A terminal count

tick is 1 while count equals LAST. At the next rising edge, count goes back to 0 instead of on to LAST + 1. So count runs 0, 1, 2 and so on to LAST, which is LAST + 1 values, and tick is 1 for one cycle in every LAST + 1. A value that ends the count like this is a terminal count. For a tick once in every N cycles, LAST is N − 1, not N, because the count starts at 0.

Figure 1 is the simulation with the defaults. The reset holds count at 0, and then tick comes once in every five cycles.

Wide enough

count must be wide enough to hold LAST. As in lesson 1.1, each bit doubles what a vector can hold: 3 bits hold 0 to 7, and 4 bits hold 0 to 15. A counter with no terminal count goes from its top value to 0, because the bit that does not fit is lost. That is how blink's counter went round and round.

The reset line comes first, so at an edge where rst is 1, count becomes 0 wherever it was, and the next lap starts from there. '0 is 0 in every bit, whatever the width of the vector it goes into, so the line still fits if BITS changes.

Question 3 of 3. Find the bug

This counter should make tick 1 for one cycle in every five. Its testbench fails. Pick the line that is wrong.

hdl/level-04/tick_gen_bug/tick_gen_bug.sv

  • 1// tick should be 1 for one cycle in every five. count goes 0, 1, 2 and so
  • 2// on up to LAST, then back to 0; tick is 1 during the cycle when count is
  • 3// LAST.
  • 4module tick_gen_bug #(
  • 5 parameter int BITS = 3,
  • 6 parameter logic [BITS-1:0] LAST = 5
  • 7) (
  • 8 input logic clk,
  • 9 input logic rst,
  • 10 output logic tick
  • 11);
  • 12 logic [BITS-1:0] count;
  • 13
  • 14 assign tick = (count == LAST);
  • 15
  • 16 always_ff @(posedge clk) begin
  • 17 if (rst) count <= '0;
  • 18 else if (tick) count <= '0;
  • 19 else count <= count + 1;
  • 20 end
  • 21endmodule
Show answer and explanation

The bug is on line 6, parameter logic [BITS-1:0] LAST = 5. It should read LAST = 4.

With LAST at 5, count runs 0, 1, 2, 3, 4 and 5: six values, so tick comes once in every six cycles. The count starts at 0, so one tick in every five needs LAST at 4 (lesson 4.1). Comparing count with one less than LAST on the assign line would also give a tick in every five, but then LAST would no longer be the last value count reaches, which is what the comments say it is.
