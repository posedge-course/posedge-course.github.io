0.2 HDL describes hardware, and it all works at once

Teaches assign statement (primitive). About 4 minutes.

In a program, line 2 runs after line 1. In a hardware description language (HDL) such as SystemVerilog, each assign line describes a piece of a circuit. All the pieces exist at once, and all of them work all the time.

Reading alarm.sv

Listing 1 is a burglar alarm. A module is a named piece of hardware, here alarm. Its ports, listed at the top, are its inputs and outputs. logic declares a signal: a wire that carries 0 or 1. opening is a signal inside the module, not a port.

assign connects a signal to the logic that drives it, for good: whenever an input changes, the signal follows. As in lesson 0.1, & means "and" and | means "or".

No before and after

Look at the order. The first assign uses opening, and the second line makes it. In a program that would be a bug, because the first line would read opening before anything set it. Here the two lines are two gates, small circuits that each work out one operation: an OR gate makes opening, an AND gate makes siren, and a wire joins them (Figure 1, top). Both exist, so neither comes first.

The same holds in time. In the simulation, siren changes in the same step as the input that caused it. Nothing waits for anything until level 2 brings in flip-flops.

What Vivado builds

Vivado folds both lines into one LUT3 (Figure 1, bottom). siren depends on three inputs, and one LUT holds any function of up to six (lesson 0.1). The wire opening disappears into the LUT's truth table. A LUT has no first line at all.

Questions

Question 1 of 3. Predict siren

Each column is one step. opening is 1 when the door or the window is open, and siren is 1 when armed and opening are both 1. Steps 0 and 1 are drawn for you. Set siren for the rest.

Question 2 of 3. Fill the blank

opening should be 1 when the door or the window is open. Type the missing operator.

hdl/level-00/alarm/alarm.sv

1// A burglar alarm: the siren sounds when the alarm is armed and the door
2// or the window is open.
3module alarm (
4 input logic armed, // 1 when the alarm is switched on
5 input logic door_open, // 1 while the door is open
6 input logic window_open, // 1 while the window is open
7 output logic siren // 1 to sound the siren
8);
9 logic opening; // 1 when the door or the window is open
10
11 assign siren = armed & opening; // uses opening before the next line
12 assign opening = door_open (blank) window_open;
13endmodule
Show answer and explanation

The blank is |. Also accepted: ||.

| means or: opening is 1 when door_open is 1, or window_open is 1, or both. With & the alarm would only notice the door and the window open together. (|| gives the same result on single bits, but this course uses |.)

Question 3 of 3. Choose the answer

alarm.sv uses opening on its first assign line and makes it on the second. What happens?

  • It works exactly as if the two lines were the other way round.
  • siren uses the old value of opening, so it is one step late.
  • It does not build: opening is used before it is set.
  • siren is unknown until opening has been set.
Show answer and explanation

The answer: It works exactly as if the two lines were the other way round.

The two lines are not steps run one after the other. They describe an OR gate and an AND gate joined by the wire opening, and both exist and work all the time, so their order does not matter. That is why, in the simulation, siren changes in the same step as its inputs, and why Vivado folds both lines into one LUT3. "One step late" and "used before it is set" are how a program behaves, not hardware.
