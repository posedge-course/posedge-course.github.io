0.3 The build flow in one picture

Teaches Build flow (design). About 5 minutes.

vote.sv says what the hardware does. It does not say where on the chip it goes, or which pins its ports use. Vivado works out where everything goes in fixed steps (Figure 1), and another file names the pins.

Synthesis

Synthesis turns the code into the FPGA's cells: the LUT3 of lesson 0.1, plus an input buffer (IBUF) for each input pin and an output buffer (OBUF) for each output pin. The buffers join the pins to the logic inside the chip.

Constraints

The code never names a pin. A constraints file does, in Vivado's XDC format. Listing 1 is the one for vote. Each set_property PACKAGE_PIN line ties one port, named by get_ports, to one pin of the chip. Port a is on pin A8, which the board wires to switch SW0; the comment above each line says which switch or LED its pin reaches. The last line tells Vivado that all four pins use 3.3 V signals (LVCMOS33), the voltage the board supplies to them.

Place and route

Place and route puts each cell somewhere on the chip and wires them together. Placement chooses one of the FPGA's tens of thousands of LUTs for the LUT3. Routing joins it to the pins the constraints file named, through the chip's wiring.

The bitstream

Vivado then writes the bitstream: one file holding the bits of every LUT and every routing connection. Programming loads it into the FPGA, which then is the circuit.

Synthesis and place and route also write reports. The Utilization report counts the cells the design uses and how many the chip has, and its first lines say which step it comes from. The questions read the real reports Vivado wrote for vote.

A build takes minutes. Lesson 0.4 shows how to check a design in seconds before you build it.

Questions

Question 1 of 3. Put the steps in order

Put Vivado's steps in order, from your files to a configured chip.

  • Programming loads the bitstream into the FPGA.
  • Place and route gives each cell a place on the chip and wires them together.
  • Synthesis turns the code into cells, such as LUTs and pin buffers.
  • Vivado writes the bitstream.
  • Write the design and its constraints file.
Show answer and explanation

In order:

  1. Write the design and its constraints file.
  2. Synthesis turns the code into cells, such as LUTs and pin buffers.
  3. Place and route gives each cell a place on the chip and wires them together.
  4. Vivado writes the bitstream.
  5. Programming loads the bitstream into the FPGA.

Each step needs the one before it. Synthesis decides which cells the code needs; place and route decides where each one goes and how they connect; the bitstream records all of that in one file; programming loads the file into the chip.

Question 2 of 3. Read the report

Vivado built vote.sv for the Arty A7-100T. Below is the Primitives table of its Utilization report: one row for each kind of cell, with how many the design uses.

vivado/reports/vote/arty-a7-100t/utilization.rpt, lines 180 to 186. Written by Vivado.

180+----------+------+---------------------+181| Ref Name | Used | Functional Category |182+----------+------+---------------------+183| IBUF     |    3 |                  IO |184| OBUF     |    1 |                  IO |185| LUT3     |    1 |                 LUT |186+----------+------+---------------------+

How many input buffers did synthesis add for vote's input pins?

Show answer and explanation

The report says 3.

An input buffer, IBUF, joins one input pin to the logic inside the chip, so synthesis adds one for each input port. vote has three inputs, a, b and c, and the IBUF row matches them. Its one output, y, has its own OBUF, and the LUT3 row is the LUT of lesson 0.1.

Question 3 of 3. Read the report

This part of vote's Utilization report is about the FPGA's pins. A bonded IOB (input/output block) is the circuit behind one of the chip's pins: "bonded" means joined to a pin of its package. Used counts the pins this design uses. Fixed counts those whose place the constraints file gave, instead of Vivado choosing it.

vivado/reports/vote/arty-a7-100t/utilization.rpt, lines 122 to 125. Written by Vivado.

122+-----------------------------+------+-------+------------+-----------+-------+123|          Site Type          | Used | Fixed | Prohibited | Available | Util% |124+-----------------------------+------+-------+------------+-----------+-------+125| Bonded IOB                  |    4 |     4 |          0 |       210 |  1.90 |

How many of vote's pins did its constraints file fix?

Show answer and explanation

The report says 4.

vote.xdc has one PACKAGE_PIN line for each of vote's four ports, a, b, c and y, so every pin vote uses is fixed, and the Used and Fixed columns agree. Vivado still chose where the LUT3 went, but not the pins: the board wires its switches and LEDs to particular pins, and only the constraints file says which.
