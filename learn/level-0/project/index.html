Level 0

Level 0 project Run a simulation and read its waveform

Install a simulator and a waveform viewer, run vote's testbench until it prints TEST PASSED, and check y in the waveform against lesson 0.1's truth table. About 45 minutes in simulation.

In this project you run a real simulation on your own computer: lesson 0.1's majority vote, with the testbench of lesson 0.4. Then you break the vote on purpose and use the TEST FAILED lines and the waveform to find where it goes wrong. You need only your computer. Installing the two tools takes most of the time, and how long depends on your system.

Installing the tools

These routes were written in October 2026. If a package name is not found, the tool's own documentation (under "Further reading") has the current one.

  • Windows: install MSYS2, open its UCRT64 terminal and run pacman -S mingw-w64-ucrt-x86_64-iverilog. Run the commands of this project in that terminal. It starts in its own home folder, so go to your project folder with cd, writing C:\Users\you\posedge as /c/Users/you/posedge.
  • macOS: install Homebrew (see "Further reading"), then run brew install icarus-verilog.
  • Linux: install your distribution's iverilog package, for example sudo apt install iverilog on Debian or Ubuntu. Older releases of these give you an older version (see below).
  • A waveform viewer: GTKWave is a package in MSYS2 (mingw-w64-ucrt-x86_64-gtkwave) and on Linux (gtkwave). On macOS, run brew install surfer. Surfer also has downloads for Windows, Linux and Apple-silicon Macs on its website.

This course checks every file with Icarus Verilog 13. The projects were also run on Icarus Verilog 12.0, the version Ubuntu 24.04 installs, so version 12 or later is known to work. An older version may work too, but it has not been checked.

Two commands

iverilog -g2012 -o vote_sim vote_tb.sv vote.sv compiles the testbench and the design together into one simulation, vote_sim. -g2012 turns on SystemVerilog, which these files use. vvp vote_sim runs it: it prints the testbench's verdict and writes vote_tb.vcd, the waveform file.

What you see when it works

  • vvp prints TEST PASSED. It also prints a line about the VCD file and one saying where $finish was called; both are normal.
  • In the counting part of the waveform, y is 1 in exactly four steps: 011, 101, 110 and 111 (Figure 1).
  • After the change in the step that breaks it, the run prints four TEST FAILED lines. They are for the rows 110 and 101, each of which the testbench tries twice, once in each part. The first is TEST FAILED: a=1 b=1 c=0 y=0, expected 1 at 20 ns.
  • alarm prints TEST PASSED too.

If it fails

  • syntax error, or a line ending requires SystemVerilog.: the command lacks -g2012. Add it.
  • Unknown module type: vote: the command names only the testbench. Name both files.
  • vote_sim: Unable to open input file.: vvp found no vote_sim. Run it in the folder where you ran iverilog, after iverilog has worked.
  • The terminal cannot find iverilog: it is not on your path, the list of folders the terminal looks in. The message depends on your system. On Windows, use MSYS2's UCRT64 terminal; elsewhere, open a new terminal after installing.
  • The viewer still shows the old waveform after you break the vote: each run writes vote_tb.vcd again, so reload it, or close it and open it again.

These messages are from Icarus Verilog 13; version 12 prints the same.

Your checklist

Simulation path

  1. Install Icarus Verilog, by the route for your system above. Check it with iverilog -V: the first line it prints names the version.
  2. Install a waveform viewer, Surfer or GTKWave.
  3. Make a new folder and save vote.sv and vote_tb.sv into it from the list above.
  4. Open a terminal in that folder and run iverilog -g2012 -o vote_sim vote_tb.sv vote.sv. -g2012 turns on SystemVerilog, which these files use. It prints nothing when it works.
  5. Run vvp vote_sim. Among the lines it prints is TEST PASSED, and it writes vote_tb.vcd into the same folder.
  6. Open vote_tb.vcd in the viewer: in the same terminal, run gtkwave vote_tb.vcd or surfer vote_tb.vcd. The viewer opens with no signals drawn. Click vote_tb in its list of scopes, then add a, b, c and y.
  7. From 80 ns to 160 ns the inputs count from 000 to 111. Check that y matches the truth table of lesson 0.1 in all eight steps. Figure 1 shows the same part of the run.
  8. In vote.sv, change the first | to &. Compile and run again, and read the TEST FAILED lines: each time is the end of a step that failed. Reload the waveform and look at those steps. Then change & back to | and run again.
  9. Save alarm.sv and alarm_tb.sv into the same folder and run them the same way, with alarm in place of vote in both commands. It prints TEST PASSED, although siren's line uses opening before the line that makes it (lesson 0.2).
