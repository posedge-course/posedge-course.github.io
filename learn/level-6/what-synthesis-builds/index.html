6.1 What synthesis builds

Teaches Netlist (design). About 5 minutes.

Lesson 0.3 said that synthesis turns code into cells. This level looks at what it builds, cell by cell. Synthesis first works out what your code describes: Listing 1 is an adder, and a register with an enable and a reset. Then it builds each of those from the cells this FPGA has. The result is a netlist: a list of cells, and the nets, the wires that join their pins.

What each cell does

Each LUT2 works out whether one bit of acc and the same bit of din differ. A CARRY4 takes four of those results, works out the carries, and gives four bits of acc + din; two of them, joined end to end, cover eight bits, and lesson 6.2 looks at them closely. Each FDRE holds one bit of acc, so the register is exactly eight flip-flops. The if and else if cost no LUT: clr goes to every R pin and en to every CE pin, as in lesson 2.4.

Synthesis chooses its cells for each design. The same code with four bits can come out quite differently, and the report is where you find out.

What synthesis leaves out

Synthesis keeps only the cells whose outputs reach a port, directly or through other cells. A register that nothing reads is removed, together with any logic that only fed it. Verilator warns about such a register before you build, as a signal that is never used.

The report

Vivado can write a Utilization report after synthesis and again after place and route (lesson 0.3). Its Primitives table has one row for each kind of cell in the netlist, with how many the design uses: for acc8, Figure 1's cells, plus the pin buffers and the clock buffer.

Questions

Question 1 of 3. Read the report

Vivado built lesson 6.1's acc8, an 8-bit register that adds din to itself at each rising edge where en is 1, for the Arty A7-100T. Below is the Primitives table of its Utilization report: one row for each kind of cell in the netlist, with how many the design uses.

vivado/reports/acc8/arty-a7-100t/utilization.rpt, lines 180 to 188. Written by Vivado.

How many FDRE flip-flops does acc8 use?

Show answer and explanation

The report says 8.

Read the FDRE row: eight, one flip-flop for each bit of acc, as lesson 6.1's Figure 1 draws them. The LUT2 and CARRY4 rows are the adder, and IBUF, OBUF and BUFG are the pins and the clock.

Question 2 of 3. Predict acc[3]

acc4 is lesson 6.1's acc8 with 4-bit din and acc: at each rising edge where en is 1, acc adds din, and clr sets it to 0, winning over en. din is drawn in hexadecimal, and acc is 0 in cycle 0. Set acc[3], the top bit of acc, for every cycle.

Question 3 of 3. Find the bug

sum_reg_bug should add a and b through a register: sum should show a + b one cycle after a and b were set. Verilator warns that total is never used. Pick the line that is wrong.

hdl/level-06/sum_reg_bug/sum_reg_bug.sv

  • 1// Adds a and b through a register: sum shows a + b one cycle after a and
  • 2// b were set.
  • 3module sum_reg_bug (
  • 4 input logic clk,
  • 5 input logic [7:0] a,
  • 6 input logic [7:0] b,
  • 7 output logic [8:0] sum
  • 8);
  • 9 logic [8:0] total;
  • 10
  • 11 always_ff @(posedge clk)
  • 12 total <= a + b;
  • 13
  • 14 assign sum = a + b;
  • 15endmodule
Show answer and explanation

The bug is on line 14, assign sum = a + b;. It should read assign sum = total;.

assign sum = a + b; reads the inputs, so sum follows them at once and nothing reads total. Synthesis keeps only what reaches a port, so it removes total's nine flip-flops and the adder that fed them. Verilator's warning points at the line that declares total, but declaring it is fine; the assign should read total.
