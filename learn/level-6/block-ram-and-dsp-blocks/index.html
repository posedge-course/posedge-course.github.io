6.3 Block RAM and DSP blocks

Teaches Block RAM (primitive), DSP block (primitive). About 7 minutes.

Lesson 6.1's cells are small. The chip also has larger blocks for two jobs that would otherwise take many of them: memories and multiplications.

Block RAM

A block RAM is a memory of 18 or 36 kilobits beside the logic. Listing 1 describes a memory of 1,024 bytes.

mem is an array: the range after its name gives it 1,024 entries, each an 8-bit vector, and mem[addr] is the entry that addr picks. A block RAM reads only at a clock edge, so Vivado can use one only for an array read at an edge, as this one is. For an array this size it did: it built ram1k from a single RAMB18E1, with no LUT and no flip-flop.

Read an array with no edge, and Vivado builds it from LUTs used as memory instead, called distributed RAM: a LUT6 used this way holds 64 bits, one for each of 64 addresses. For ram64, 64 bytes read with no edge, that is fine. For 1,024 bytes it takes 128 LUTs to hold the bits, and more to pick each one out, where one block would have done.

DSP blocks

A DSP block holds a multiplier, an adder after it, and registers. This chip's is the DSP48E1, which multiplies a 25-bit number by an 18-bit one. Vivado decides when to use one: it put the product of mul16, one * on two 16-bit numbers, in a DSP48E1, but built mul8's 8-bit product from LUTs and carry chains.

The DSP48E1's registers save flip-flops, if your code has registers where it does. Listing 2 keeps a and b in registers, then their product, so all 64 register bits can be the DSP48E1's own. Each register adds an edge: the product arrives two edges after its numbers, so the flag that says which cycles hold real numbers goes through two flip-flops to arrive with it, as lesson 4.3's shift register did.

How many LUTs does ram64 use as memory?

Show answer and explanation

The report says 8.

Read the LUT as Memory row: eight. A LUT6 used as memory holds 64 bits, one for each of 64 addresses, so one LUT holds one bit of every byte, and a byte has eight bits. LUT as Logic is 0: reading needs nothing beyond the memory LUTs themselves.

How many flip-flops does mul16 use?

Show answer and explanation

The report says 0.

Read the Register as Flip Flop row: 0. p's register comes straight after the multiplier, where the DSP48E1 has registers of its own, so Vivado used those, and all 32 bits of p are inside the block. Slice LUTs is 0 too: the DSP48E1 does the whole job.

Question 5 of 5. Find the bug

ram1k_bug should behave like lesson 6.3's ram1k: dout should follow a new addr one cycle later, so that Vivado can build it from block RAM. Its testbench, the same as ram1k's, fails. Pick the line that is wrong.

Show answer and explanation

The bug is on line 16, assign dout = mem[addr];. It should read always_ff @(posedge clk) dout <= mem[addr];.

assign dout = mem[addr]; reads the array with no clock edge, so dout follows addr at once and the testbench sees each entry a cycle early. That is also why Vivado cannot use block RAM, which reads only at an edge: it builds this memory from LUTs. Reading at the edge, dout <= mem[addr]; in an always_ff block, gives ram1k's timing and its RAMB18E1.
