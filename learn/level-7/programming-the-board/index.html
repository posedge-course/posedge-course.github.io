7.3 Programming the board

Teaches Programming the board (design). About 5 minutes.

Levels 1 to 4 ended by programming the board: Generate Bitstream, then the Hardware Manager, Open Target, Auto Connect and Program Device. This lesson says what those steps do, and how to hear back from the board.

From your PC into the chip

The bitstream holds the whole configuration: the bits of each LUT, the start value of each flip-flop and every routing switch, about 30 million bits for this chip. The FPGA keeps them in its configuration memory, beside the logic they set up. Program Device sends them over the board's USB cable to a USB-JTAG circuit on the board, which loads them into the chip. When the last bit is in, the board's DONE LED lights, and the chip is your circuit, with every flip-flop at its start value (lesson 2.3).

Only while it has power

Configuration memory forgets everything at power-off. At power-on, if the board's mode jumper says so, the FPGA loads the design that the board's flash memory holds instead. So programming over USB lasts until you unplug the board. Writing a design into the flash keeps it; this course does not need that.

A bitstream is built for one part, and the header at the top of every Vivado report names it. An Arty A7-35T and an A7-100T need different builds, as level 1's project said.

Hearing back

The same cable carries the board's serial line to your PC, where it appears as a serial port. Level 5's project drove such a line with a UART (universal asynchronous receiver-transmitter): a circuit that sends bytes one bit at a time on one wire. A serial terminal, a program such as PuTTY on Windows or screen on macOS and Linux, shows what arrives there as text. It must listen as the design sends: 115,200 bits a second, the baud rate, with 8 data bits, no parity bit (a check bit that some links add to each character) and 1 stop bit. A terminal set to another rate reads each bit at the wrong moment and shows the wrong characters, or none.

Questions

Question 1 of 3. Put the steps in order

Your design passes its testbench, and the board is plugged in by USB. Put in order the steps that put the design on the board.

  • Program Device, with the bitstream Vivado wrote.
  • The DONE LED lights, and your design runs.
  • Run Generate Bitstream.
  • Open the Hardware Manager.
  • Open Target, then Auto Connect: Vivado finds the FPGA on the board.
Show answer and explanation

In order:

  1. Run Generate Bitstream.
  2. Open the Hardware Manager.
  3. Open Target, then Auto Connect: Vivado finds the FPGA on the board.
  4. Program Device, with the bitstream Vivado wrote.
  5. The DONE LED lights, and your design runs.

The bitstream must exist before anything can be programmed, and the Hardware Manager must find the board's FPGA before it can program it. DONE lights when the FPGA has loaded the whole bitstream, and from then on the chip is your circuit.

Question 2 of 3. Read the report

Every Vivado report starts with a header that names the design and the part it was built for. Below are two lines of the header of hello's Utilization report.

vivado/reports/hello/arty-a7-100t/utilization.rpt, lines 7 to 8. Written by Vivado.

7| Design       : hello8| Device       : xc7a100tcsg324-1

Which part was hello built for?

Show answer and explanation

The report says xc7a100tcsg324-1.

xc7a100tcsg324-1, the Artix-7 100T in the 324-pin package on the Arty A7-100T. A bitstream fits only the part it was built for: an Arty A7-35T needs a build for its own part, xc7a35ticsg324-1L, as level 1's project said.

Question 3 of 3. Fill the blank

The terminal on your PC will listen at 115,200 baud: 115,200 bits a second. hello passes LAST to its uart_tx, which makes each bit last LAST + 1 cycles of the board's 100 MHz clock. Fill in LAST.

hdl/level-07/hello/hello.sv, lines 4 to 9

4module hello #(
5 parameter int TBITS = 10, // uart_tx's timer width
6 parameter logic [TBITS-1:0] LAST = (blank), // 115,200 baud at 100 MHz
7 parameter int PBITS = 20, // press's counter width
8 parameter logic [PBITS-1:0] HOLD = 999_999 // about 10 ms at 100 MHz
9) (
Show answer and explanation

The blank is 867. Also accepted: 10'd867.

One bit lasts 100,000,000 ÷ 115,200 = 868 cycles, to the nearest cycle, and the timer counts 0 to LAST, so LAST is 867. A design and a terminal set to different rates still exchange bits, but each side reads them at the wrong moments, and the terminal shows the wrong characters.
