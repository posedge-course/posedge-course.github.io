7.2 Describing the clock

Teaches Clock constraint (primitive). About 5 minutes.

Every flip-flop in your design takes its input at a rising edge of clk, and the logic between two flip-flops must settle before the next edge. Whether it does depends on how far apart the edges are, and nothing in your code says. The board does: its oscillator runs at 100 MHz, a rising edge every 10 ns. That time is the clock's period.

The create_clock line

Listing 1 is the part of tick_led.xdc that describes this clock to Vivado: a clock constraint. -period 10.00 is the period in nanoseconds, [get_ports clk] the port the clock arrives on, and sys_clk_pin a name the reports use for it.

With a period, Vivado can check every path from one flip-flop to the next: it adds up the delays of the cells and wires along the path and compares the total with the period. The timing summary's first number, WNS (worst negative slack), is the smallest time to spare it found, in nanoseconds. Positive means every path arrives in time. Level 8 reads the rest of the report.

It describes; it never sets

The line only describes. Leave it out and the build still finishes, but Vivado has no period to check against: the timing summary counts the flip-flops that have no clock, and checks no path at all. Give it the wrong period and Vivado checks the wrong clock, and may well report every path met, while the board's edges still come every 10 ns. Nothing in a constraints file changes how fast the board runs.

Questions

Question 1 of 3. Fill the blank

A learner believed the Arty's clock ran at 50 MHz, and wrote this constraints file for tick_led to say so. Fill in the period that describes a 50 MHz clock.

vivado/projects/tick_led_20ns/tick_led_20ns.xdc, lines 4 to 5

4set_property PACKAGE_PIN E3 [get_ports clk]
5create_clock -name sys_clk_pin -period (blank) [get_ports clk]
Show answer and explanation

The blank is 20.00. Also accepted: 20, 20.0.

A period is one second divided by the frequency: 1 ÷ 50,000,000 s is 20 ns, so the line says -period 20.00. It describes a clock the board does not have; the board's oscillator runs at 100 MHz, a period of 10.00, whatever the file says.

Question 2 of 3. Read the report

tick_led_noclock is level 4's tick_led built with its create_clock line left out. Below is one of the checks at the start of its timing summary.

vivado/reports/tick_led_noclock/arty-a7-100t/timing_summary.rpt, lines 65 to 67. Written by Vivado.

651. checking no_clock (28)66-------------------------67 There are 28 register/latch pins with no clock driven by root clock pin: clk (HIGH)

How many register pins does the report say have no clock?

Show answer and explanation

The report says 28.

28: the clock pins of tick_led's 28 flip-flops, 27 for the count and one for led. Vivado can see that clk drives them, but with no create_clock it has no period, so it checks no path between them. The build still finishes, and the timing summary says there are no timing constraints at all.

Question 3 of 3. Put the steps in order

Put in order what Vivado does, during a build, with tick_led.xdc's create_clock line.

  • It reads create_clock: the clock on clk has a period of 10 ns.
  • It compares each path with the 10 ns between rising edges.
  • Its timing summary gives the smallest time to spare as WNS.
  • It finds every path from one flip-flop to the next.
  • It adds up the delays of each path's cells and wires.
Show answer and explanation

In order:

  1. It reads create_clock: the clock on clk has a period of 10 ns.
  2. It finds every path from one flip-flop to the next.
  3. It adds up the delays of each path's cells and wires.
  4. It compares each path with the 10 ns between rising edges.
  5. Its timing summary gives the smallest time to spare as WNS.

The period comes first: without it there is nothing to check against. Then each path between flip-flops is found and its delays added up, and only then can a path be compared with the period. WNS, the smallest margin over every path, can be known only once all of them are compared.
