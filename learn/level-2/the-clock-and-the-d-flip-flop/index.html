2.1 The clock and the D flip-flop

Teaches D flip-flop (primitive). About 5 minutes.

Everything you have built on purpose so far changes as soon as its inputs change. That is fine for working something out, but not for remembering it. The latch of lesson 1.4 did remember, but by accident: whenever a path happened to give its output no value. To remember on purpose, a circuit needs a moment when it looks at its input and then holds what it saw until next time. In almost every FPGA design, that moment comes from a clock: a signal that switches between 0 and 1, on and on, at a steady rate.

The clock on the Arty A7 board runs at 100 MHz: one full cycle every 10 ns. The instant it goes from 0 to 1 is a rising edge, and from 1 to 0 a falling edge. The diagrams in this course mark each rising edge with a small arrowhead.

The D flip-flop

A D flip-flop does the remembering. It has a data input d, a clock input and an output q. At each rising edge it copies d to q. Between edges it ignores d completely, and q keeps the value it took at the last edge.

So two rules let you read any flip-flop on any waveform:

  • q changes only at a rising edge.
  • Just after an edge, q equals what d was at that edge.

Figure 1 shows what Vivado builds from this lesson's code: a single cell called FDRE, a D flip-flop with two extra inputs, a clock enable (CE), which can make it skip an edge (lesson 2.4), and a reset (R), which can clear it (lesson 2.3). This design uses neither, so CE is tied to 1 and R to 0. The FPGA on the Arty A7-100T has 126,800 of these flip-flops.

In SystemVerilog

always_ff @(posedge clk) means "at every rising edge of clk, do this". The line inside, q <= d;, copies d to q. For now, read <= as "becomes, at the edge". The next lesson explains why it is not =.

Question 1 of 4. Predict q

Question 3 of 4. Fill the blank

This is lesson 2.1's flip-flop, dff.sv, with one word missing. Type the word that makes it copy d to q at each rising edge of clk.

hdl/level-02/dff/dff.sv

1// A D flip-flop: at every rising edge of clk, q takes the value d had
2// just before the edge, then holds it until the next rising edge.
3module dff (
4 input logic clk, // the clock
5 input logic d, // data in
6 output logic q // data out: d as it was at the last rising edge
7);
8 always_ff @((blank) clk) begin
9 q <= d;
10 end
11endmodule
Show answer and explanation

The blank is posedge.

posedge clk means the rising edge of clk, the moment it goes from 0 to 1. So always_ff @(posedge clk) copies d to q once at every rising edge, and q keeps its value in between.

Question 4 of 4. Find the bug

This flip-flop should behave like lesson 2.1's dff, but its testbench fails. Pick the line that is wrong.

hdl/level-02/dff_bug/dff_bug.sv

  • 1// A D flip-flop that should copy d to q at every rising edge of clk.
  • 2// Its testbench fails: one line is wrong.
  • 3module dff_bug (
  • 4 input logic clk, // the clock
  • 5 input logic d, // data in
  • 6 output logic q // data out: d as it was at the last rising edge
  • 7);
  • 8 always_ff @(negedge clk) begin
  • 9 q <= d;
  • 10 end
  • 11endmodule
Show answer and explanation

The bug is on line 8, always_ff @(negedge clk) begin. It should read always_ff @(posedge clk) begin.

Lesson 2.1's flip-flop says always_ff @(posedge clk): at every rising edge. This one says negedge, the falling edge, when clk goes from 1 to 0, so q changes half a cycle late. The testbench checks lesson 2.1's rule, that just after each rising edge q equals the value d had at that edge, and that fails. With posedge the same testbench passes.
