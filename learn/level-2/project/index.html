Level 2

Level 2 project Blink an LED from the board clock

Write blink in my_blink.sv until the provided testbench prints TEST PASSED, then work out from its waveform how long the LED will stay on with the default width. About 40 minutes in simulation.

For the second time you write a module from a description, and this time it has a clock. A testbench you did not write tells you whether it is right. You need only Icarus Verilog and the waveform viewer from level 0's project. The steps for the board are optional.

The module counts the cycles of the board's 100 MHz clock and shows the top bit of the count on an LED. It uses every lesson of this level: flip-flops that change at a rising edge (2.1), <= in an always_ff block (2.2), a synchronous reset (2.3) and an enable that pauses the count (2.4).

The parameter

A parameter is a constant with a default value, which a module that uses this one can change. blink_tb.sv puts a blink inside itself with #(.BITS(4)), so the simulation uses a 4-bit count and led changes every few cycles; Vivado builds the default, 27.

Two commands

The file you write is my_blink.sv, so saving the course's answer later never overwrites it. In a terminal in your folder, iverilog -g2012 -o blink_sim blink_tb.sv my_blink.sv compiles your file with the testbench; -g2012 turns on SystemVerilog, which these files use. Then vvp blink_sim runs it: it prints the testbench's verdict and writes blink_tb.vcd.

Figure 1 is the start of the run with the course's answer. Your count may have another name; the ports are the same.

What you see when it works

  • The run prints TEST PASSED.
  • In the waveform, while run is 1, led changes every 8 cycles: bit 3 changes once every 2 × 2 × 2 = 8 counts. While run is 0, the count and led wait.
  • The working-out: bit 26 changes once every 2 to the power 26 = 67,108,864 counts. At one count per 10 ns cycle that is about 0.67 s, so LD4 is on for about 0.67 s, then off for about 0.67 s. With BITS at 26, about 0.34 s each.
  • With the board, LD4 blinks at that rate while SW0 is in one position, stops while it is in the other, and stays off while BTN0 is held.

If it fails

  • syntax error, or a line ending requires SystemVerilog.: the command lacks -g2012. Add it.
  • Unknown module type: blink: the command names only the testbench, or the module in your file has another name. The file is my_blink.sv, but the module in it must be called blink.
  • parameter `BITS` not found: your module has no parameter called BITS. See the step that starts the module.
  • Every line shows led=x, from the first, TEST FAILED: led=x, expected 0 at 10 ns. x is how the simulator prints a value it does not know (lesson 2.3's "unknown"; level 3 says more). Either your count never gets a first value, so check that the rst line sets it to 0, or led reads a bit the count does not have: with logic [BITS-1:0] count, the top bit is count[BITS-1], not count[BITS] (lesson 1.1).
  • The first failure is TEST FAILED: led=1, expected 0 at 260 ns: your count does not wait while run is 0 (lesson 2.4).
  • An early failure, such as TEST FAILED: led=1, expected 0 at 30 ns, and more follow: led is not the top bit of the count.
  • The terminal cannot find iverilog: as in level 0's project, the install did not put it on your path.

These messages are from Icarus Verilog 13; version 12 prints the same.

Check yourself

If you wrote = in your always_ff block, the testbench may still pass: with one line, nothing reads the count in between. Use <= anyway (lesson 2.2); in a longer block, = changes what the lines after it read.

Your checklist

Simulation path

  1. Make a new folder and save blink_tb.sv into it from the list above. It is the specification: after every rising edge it checks led against a model of the count.
  2. In the same folder, make a file my_blink.sv. In it, start a module named blink, the name the testbench uses. Between the name and the list of ports, write parameter int BITS = 27 inside #( and ). Then give it the four ports in the table above.
  3. Declare the count as a vector of BITS bits, logic [BITS-1:0] count; (lesson 1.1). In an always_ff block (lesson 2.2), at each rising edge: if rst is 1, count becomes 0 (lesson 2.3); if not, and run is 1, it becomes count + 1; otherwise it keeps its value (lesson 2.4).
  4. Give led the top bit of the count with an assign: count[BITS-1] (lesson 1.1's bit-select).
  5. Open a terminal in the folder and run iverilog -g2012 -o blink_sim blink_tb.sv my_blink.sv. It prints nothing when it works.
  6. Run vvp blink_sim. Change your file and run both commands again until it prints TEST PASSED.
  7. Open blink_tb.vcd in the viewer and add clk, run and led from blink_tb, and your count from inside dut. While run is 1, count the cycles between two changes of led, and check what led does while run is 0.
  8. With BITS at 4, led is bit 3 of the count. With the default, 27, it is bit 26. Work out how many cycles bit 26 stays the same, and how long that is at 10 ns a cycle. Then compare your answer with "What you see when it works" above.

On the board (optional)

  1. In Vivado, create an RTL project for the part xc7a100tcsg324-1 (on an Arty A7-35T, xc7a35ticsg324-1L), as in level 1's project. Add your my_blink.sv as a design source and the saved blink.xdc as a constraints file.
  2. Run Generate Bitstream and wait until Vivado says it has finished.
  3. Open the timing summary of the implemented design and find the line that says whether the timing constraints are met. The clock line of blink.xdc asks for a 10 ns cycle, and Vivado checks that every flip-flop's next value is ready in time. Listing 1 above is that line from the course's build.
  4. Connect the board by USB. Open the Hardware Manager, then Open Target, Auto Connect and Program Device.
  5. Move SW0 one way, then the other: in one position LD4 blinks. Time it against your working-out.
  6. Move SW0 back while LD4 is on, or while it is off: it stays as it is. Move SW0 again and it carries on.
  7. While it blinks, hold BTN0: LD4 goes off and stays off. Let go: it starts again from the beginning, off.
  8. Change BITS to 26 in your file, then build and program again. Work out the new time first, then watch.
