2.4 Registers with enables

Teaches Register with enable (circuit). About 5 minutes.

Assign a vector in always_ff and you get one flip-flop for each bit, all on the same clock. Together they are a register: a row of flip-flops that holds a number. Listing 1 is a 4-bit register.

A register often should change only sometimes. Here load decides when. At a rising edge where load is 1, q takes d. At an edge where load is 0, no line gives q a value, so the flip-flops keep the one they have. load is an enable, like the latch's in lesson 1.4: it says when something may happen.

In lesson 1.4, a path that gave an output no value made a latch, a memory you did not ask for. Here memory is what you want. Flip-flops keep their value between edges anyway, and an edge where no line gives q a value is one more edge where they keep it.

Reset first

The block tests rst before load. At an edge where both are 1, the if (rst) line runs and the line below it does not, so q becomes 0: the reset wins. Written the other way round, load would win. As in lesson 2.3, this reset is synchronous.

No logic for the enable

Figure 1 shows what Vivado builds: four FDREs, one for each bit. An FDRE's clock enable, CE, decides whether it takes D at an edge, so Vivado joins load to all four CE inputs, and rst to all four R inputs. The enable and the reset need no logic of their own.

Enables let parts of a design act only when they need to, all from one clock. Level 4 builds on them.

On the board (optional)

You need an Arty A7 and Vivado for this part. Everything above works without them.

Build reg_en with the pins in Listing 2: switches SW0 to SW3 are d, BTN1 is load, BTN0 is rst, and LEDs LD4 to LD7 show q.

After programming, the LEDs are off: these flip-flops start at 0. Set some switches and press BTN1: the LEDs copy them, and follow them while you hold it. Let go and move the switches: the LEDs keep their value. Press BTN0: they go off.

Question 4 of 4. Find the bug

This register should take d only at rising edges where load is 1, and keep its value at the others. Verilator warns that load is never used. Pick the line that is wrong.

hdl/level-02/reg_en_bug/reg_en_bug.sv

  • 1// A 4-bit register. At a rising edge: rst clears it; otherwise, if load
  • 2// is 1, it takes d; otherwise it keeps its value.
  • 3module reg_en_bug (
  • 4 input logic clk,
  • 5 input logic rst,
  • 6 input logic load,
  • 7 input logic [3:0] d,
  • 8 output logic [3:0] q
  • 9);
  • 10 always_ff @(posedge clk) begin
  • 11 if (rst) q <= 4'd0;
  • 12 else q <= d;
  • 13 end
  • 14endmodule
Show answer and explanation

The bug is on line 12, else q <= d;. It should read else if (load) q <= d;.

The else line gives q the value of d at every edge where rst is 0, whether load is 1 or not, so load does nothing. Verilator reports the problem where load is declared, the port line, but that line is not the mistake: deleting the port would silence the warning and leave a register that never keeps its value. Written else if (load) q <= d;, the line uses load as the comment says.
