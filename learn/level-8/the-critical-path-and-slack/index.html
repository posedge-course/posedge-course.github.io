8.2 The critical path and slack

Teaches Slack (primitive). About 5 minutes.

Every path has a time its data must arrive by, its required time: the next rising edge, less the setup time. It also has an arrival time: when its data gets there, after the clock-to-output time, the logic and the wires (lesson 8.1). The difference is the path's slack: the required time minus the arrival time.

A positive slack is time to spare. A negative slack means the data arrives too late, and the path fails. Hold has a slack too, worked out the other way round, arrival minus required, because there the data must not arrive too early (lesson 8.3). Figure 1 is lesson 8.1's model again, with a slower path: its logic takes 12 ns, 2 ns more than the period, so its slack is −2 ns.

The critical path

Vivado works out the slack of every path in a design. The path with the least is the critical path: it sets how fast the clock can be, and its slack is WNS (lesson 7.2). An endpoint is where a path ends, such as a flip-flop's D. When paths fail, the timing summary counts the failing endpoints, and gives TNS, total negative slack: their negative slacks added up.

Listing 1 is msum16. At every edge it takes a new sample and adds up the last 16, all between two edges, so its critical path runs through that sum.

Its for loop does not run over time: synthesis builds one copy of the loop's body for each value of i, all working at once. So line 14 is 15 assignments made at the same edge, each x[i] taking x[i-1]: a shift register (lesson 4.3).

msum16 meets the board's 100 MHz clock, with little to spare. msum32, the same with 32 samples, adds twice as many numbers between two edges, and misses it.

A failing path still builds

Missing timing is not an error: Vivado still places and routes the design and writes a bitstream. On the board, though, a flip-flop at the end of a failing path may take a wrong value, and nothing in simulation warns you. To make it meet, either give every path more time, with a slower clock if the design can have one, or give the critical path less to do between two edges. Lesson 8.4 does the second.

How much time does msum16's critical path have to spare, in nanoseconds?

Show answer and explanation

The report says 0.435 ns.

Read WNS: 0.435. The critical path, the one with the least slack, arrives 0.435 ns before it must, so every other path has more to spare. Sixteen samples added in one cycle fit in 10 ns, with less than half a nanosecond left over.

At how many flip-flop inputs does msum32's data arrive too late?

Show answer and explanation

The report says 5.

Read TNS Failing Endpoints: 5. An endpoint is where a path ends, here a flip-flop's D input; Vivado checked 517 of them, and at 5 the data arrives after the time it must. WNS, the worst of their slacks, is −0.500, and TNS, −1.432, is all five negative slacks added together.

Question 3 of 3. Put the steps in order

Put in order how Vivado decides, from a design's paths, that timing is not met.

  • With every path's slack known, the smallest is WNS.
  • WNS is negative, so the summary says the constraints are not met.
  • Its data reaches the D input it goes to: the arrival time.
  • A rising edge starts the path at the flip-flop it comes from.
  • The required time minus the arrival time: the path's slack.
Show answer and explanation

In order:

  1. A rising edge starts the path at the flip-flop it comes from.
  2. Its data reaches the D input it goes to: the arrival time.
  3. The required time minus the arrival time: the path's slack.
  4. With every path's slack known, the smallest is WNS.
  5. WNS is negative, so the summary says the constraints are not met.

An arrival time is counted from the edge that starts the path, so the path comes first. Slack needs the arrival time, and WNS needs every path's slack: it is the smallest of them, so it can only be known last. A single negative slack is enough for the summary to say the constraints are not met.
