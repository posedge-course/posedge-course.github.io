11.1 A decoder made of convolutions

Teaches Convolution layer (circuit). About 7 minutes.

Qubits keep picking up errors. The surface code spreads one qubit's information over a grid and keeps measuring checks between neighbours; a failed check says an error is near. The pattern of failed checks is the syndrome. Different errors can give the same syndrome, so a decoder guesses which corrections to apply. This level takes apart one built into the board's FPGA for a master's thesis: a network trained by Gicev and colleagues.

Three convolutions

At code distance 5, the surface code's size, the decoder reads a 9 × 9 grid with four bits at each position, its channels: two for the syndrome and two that mark the grid's edges. Three layers each turn one map, a grid with channels at each position, into the next: 4 channels into 9, then 9, then 2 (Figure 1). The 2 decide, at each position, whether to correct an X error and a Z error, the code's two kinds (not a simulator's X and Z).

Each layer is a convolution: at each position, a bias plus each input in a window around it times its weight, over every input channel. Each output channel has its own weights and bias, and so its own sum. The window is the kernel, and each input it reads a tap. The same weights serve every position. An 11 × 11 kernel reaches five positions past its centre; off the grid, the input reads 0, so the stored input has a border of five zeros: padding. After each hidden layer, every layer but the last, ReLU turns negative sums into 0.

With inputs 1, 0, 1, weights 2, −1, 3 and bias −1, the sum is −1 + 2 + 0 + 3 = 4. The last layer's sum is a logit, and the decision is 1 when it is more than 0: strictly, so a logit of 0 gives 0.

In hardware

Weights can be negative. A vector declared signed, as in logic signed [7:0] w0, is two's complement: in 8 bits the top bit counts −128, not 128, so all ones is −1, and a value is negative exactly when its top bit, the sign bit, is 1. 10'(bias) widens bias to 10 bits, copying its sign bit into the new bits.

conv_row (Listing 1) is a convolution in small: three taps over a row of 8 one-bit inputs, as in the decoder's first layer, one position a cycle; each product is the weight or 0.

Question 2 of 3. Fill the blank

Lesson 11.1's conv_row reads its taps from padded, ten bits: the row x with a 0 at each end, so that a tap outside the row reads 0. Fill in padded, so that the three lines under it pick position p's taps.

The blank is {1'b0, x, 1'b0}. Also accepted: {1'b0, x[7:0], 1'b0}, {1'd0, x, 1'd0}, {1'd0, x[7:0], 1'd0}.

{1'b0, x, 1'b0}. A concatenation lists its parts from the top bit down (lesson 4.3), so padded[0] is a 0, padded[1] to padded[8] are x[0] to x[7], and padded[9] is a 0. Then padded[p] is x[p-1], and reads the 0 at position 0; padded[p + 2] is x[p+1], and reads the other 0 at position 7.

Show answer and explanation

The bug is on line 45, decision <= ~logit[9];. It should read decision <= (logit > 0);.

~logit[9] is 1 whenever the sign bit is 0, and the sign bit is 0 for 0 as well as for every positive logit. A logit of exactly 0 must decide 0, so the test has to be logit > 0, strictly more than 0. The two agree everywhere else, which is why only a row with a logit of 0 shows the difference.
