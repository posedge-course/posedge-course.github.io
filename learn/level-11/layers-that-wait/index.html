11.4 Layers that wait

Teaches Readiness count (circuit). About 6 minutes.

The decoder's three layers work at once: while layer two works through the map, layer one is already further on. The first version to run on the board gave every layer one shared counter, one tap a cycle: 121 cycles a position for every layer, so the cheap first layer went at the speed of the slowest. The second gives each layer its own sequencer, the counters that choose which tap it issues next: 11, 33 and 33 cycles a position, and each starts a position as soon as its inputs are written.

Counting writes

Every map is written in raster order (lesson 11.2). Position p of layer two reads layer one's positions up to five rows down and five across, p + 5 × 9 + 5 at distance 5. Layer one counts the positions it has written. Because it writes in order, once its count is more than p + 50, every position up to p + 50 is there, and p can start. This readiness count counts finished writes: it is not a timer.

Near the end of the map the furthest position lies past the end, where nothing is written. So the test is: the count has passed the furthest position, or the producer has written the whole map.

A layer that may not start yet freezes. It keeps its place and sends empty cycles down its pipeline, cycles with no tap in them, so nothing it has half done is lost. How long it waits depends on the schedule alone, never on the syndrome, so a pass takes the same time for every input: 4,938 cycles at distance 5, where the shared counter took 22,632. Layer two's 81 positions take 2,673 of them, 33 each. Before it starts, layer one must write 51 positions: 561 cycles. After it ends, layer three still has 51 to do: 1,683. The pipeline's stages add 21.

The thesis's fastest build takes six taps a cycle in layers two and three: 3,486 cycles. It met timing (level 8) at 90 MHz, not 100: 38.73 µs, not 34.86.

A layer in small

layer_wait (Listing 1) is a layer's sequencer: N positions of T taps, each position reading R past itself. np and nt are the tap it issues next; run, p and t say which tap the last edge issued, and run is 0 for an empty cycle. In Figure 1, position 3 needs wr above 4, and the layer waits until it is.

Question 3 of 3. Find the bug

layer_wait_bug should issue every tap of all eight positions, as lesson 11.4's layer_wait does. Its testbench fails at the last position: the producer has written all 8, and the layer never starts position 7. Pick the line that is wrong.

Show answer and explanation

The bug is on line 28, assign ready = (wr > np + 4'(R));. It should read assign ready = (wr > np + 4'(R)) | (wr == 4'(N));.

Position 7 reads up to position 8, which is past the end of the map: nobody ever writes it, so wr never gets above 8. A layer may also start once the producer has written all N positions, wr == 4'(N). Without that, the last position waits for ever, and so does every layer after it.
