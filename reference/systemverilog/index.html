SystemVerilog cheat sheet

The part of SystemVerilog this course builds hardware from, and the lines its testbenches use. Every listing is lines of a file that the course lints with Verilator and runs with Icarus Verilog, so what you see is what was tested.

A module

  • A module lists its ports first, each an input or an output, then what it does.
  • logic declares a signal, a wire that carries 0 or 1.
  • assign connects a signal to its logic for good. All the lines work at once, so their order does not matter.

Vectors and numbers

  • logic [3:0] a is four bits, numbered 3 down to 0; bit 0 is worth 1.
  • sum[3:0] takes bits 3 to 0, a part-select, and sum[4] takes one bit, a bit-select.
  • Work out each width from the largest value it must hold. The sum of two N-bit numbers needs N + 1 bits. Give it only N and its top bit is lost, with no complaint from any tool, since every width matches.
  • A sized number gives its width, its base and its value: 2'd1 is decimal, 4'b0110 binary and 8'hFF hexadecimal. '0 is 0 in every bit, whatever the width.

Operators

Logic: always_comb

  • always_comb describes logic: outputs worked out from the inputs as they are now. Assign with =.
  • Give every output a value on every path: a default assignment as the first line (Listing 3), or an else for every if and a default for every case (Listing 4). A path that gives an output no value builds a latch.

Flip-flops: always_ff

  • always_ff @(posedge clk) runs its lines at each rising edge of clk, and only then.
  • Assign with <=: every right-hand side is read before any left-hand side changes, so q2 takes the value q1 had before the edge.
  • A synchronous reset is the first if, so it wins over the enable. At an edge where no line gives a register a value, it keeps the one it has.

An asynchronous reset

The reset's rising edge joins the clock's in the event list, and the if tests the reset first. The course uses synchronous resets unless a lesson says otherwise.

Parameters and instances

  • Parameters come before the ports, each with the value an instance gets if it sets none.
  • An instance names the module, sets its parameters with #(.LAST(LAST)), names itself, and joins each port by name: .clk(clk).

Shift registers

{q[2:0], d} joins three bits and one into four: at each edge every bit moves up one place and d comes in at the bottom.

State machines

  • typedef enum names the states; state is the state register and next the state it takes at the next edge.
  • The next-state logic is always_comb, starting with next = state;, and the state register is always_ff.
  • default sends any code that no state uses back to a safe state. Vivado may drop that way back unless the fsm_safe_state attribute on the state register tells it to keep one (lesson 5.3).

Memories

logic [7:0] mem [0:1023] is an array of 1,024 bytes. Read it at a clock edge (Listing 12) and Vivado can build it from block RAM; read it with no edge (Listing 13) and it builds it from LUTs, as distributed RAM.

Signed numbers

  • logic signed [3:0] w is two's complement, −8 to 7: the top bit counts −8.
  • If one operand is unsigned, the whole expression is worked out unsigned. So act, never negative, gets a 0 on top and $signed before it meets w.
  • 20'(bias) makes bias 20 bits wide and copies its sign bit into the new bits.

Loops

A for loop in a design does not run over time: synthesis builds one copy of its body for each value of i, all working at once. Line 14 is 15 assignments made at the same edge, each x[i] taking x[i-1]: a shift register (lesson 8.2).

Attributes

An attribute, between (* and *), is a note to Vivado about the declaration after it. ASYNC_REG marks two flip-flops as a synchroniser (lesson 9.2).

In testbenches only

  • The first line makes a time unit 1 ns. A testbench has no ports.
  • initial runs once, from time 0; always starts again each time it finishes. #5 waits 5 units, @(posedge clk) the next rising edge and @(negedge clk) the next falling one.
  • $dumpfile and $dumpvars record the waveform, $display prints and $finish stops.

A task is a named list of testbench lines. Its check uses !==, so a q that is X fails instead of slipping past.

Not in a design file

  • # delays, which synthesis drops, and $display and $finish, which build nothing.
  • initial to give a register its start value: the course uses a reset instead.
  • A block on both edges of one clock, which synthesis refuses.
  • = in always_ff, which lets a later line read the new value.
  • A clock made from logic, such as a counter bit: keep one clock, and make a tick for an enable.
