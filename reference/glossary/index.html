Symbols

!== (case inequality)
The opposite of ===: 1 when two values differ in any bit, X and Z included. Testbench checks use it, because an X cannot slip past it as it can past !=. Lesson 3.3 Self-checking testbenches
& (and)
The and operator: 1 when both sides are 1. On a vector it works on each bit separately. Lesson 0.1 What is inside an FPGA
^ (exclusive or)
Exclusive or: 1 when its two sides differ. level_a ^ pulse_a is level_a flipped when pulse_a is 1. Lesson 9.3 Pulses, handshakes and buses
== (equals)
Compares two values: 1 when they are equal, 0 when not, as in if (sel == 2'd0). Lesson 1.4 The accidental latch
=== (case equality)
Compares two values bit by bit, with X and Z as values of their own, so it always gives 0 or 1, never X. Lesson 3.3 Self-checking testbenches
>> (shift right)
Moves every bit of a vector down: wbin_next >> 1 is the count with each bit one place lower and a 0 at the top. Lesson 9.4 Asynchronous FIFOs and resets
| (or)
The or operator: 1 when either side is 1, or both. On a vector it works on each bit separately. Lesson 0.1 What is inside an FPGA
~ (not)
The not operator: it turns 0 into 1 and 1 into 0, bit by bit. Lesson 1.2 Operators become look-up tables
$finish
Stops the simulation. Without it, a testbench's clock would go on flipping for ever. Lesson 3.1 Anatomy of a testbench

A

activation
A hidden layer's output value, after ReLU, which the next layer reads: an unsigned 8-bit number in the 3D decoder. Lesson 12.1 A decoder that sees time
active high
Reading 1 while active, like the Arty's push buttons, which read 1 while pressed. Lesson 7.4 Works in simulation, dead on the board
active low
Reading 0 while active, like the Arty's red RESET button, which reads 0 while pressed. Lesson 7.4 Works in simulation, dead on the board
always block
A testbench block that starts again each time it finishes. With a delay and a line that flips the clock, it makes a clock for ever. Lesson 3.1 Anatomy of a testbench
always_comb
A block that describes logic: outputs worked out from the inputs as they are now, with statements such as if and case, assigning with =. Every path through it must give every output a value. Lesson 1.3 Multiplexers with ?:, if and case
always_ff
A block that describes flip-flops: with @(posedge clk), its lines run at each rising edge of clk, and only then. Assign in it with <=. Lesson 2.2 always_ff and why assignments use <=
array
A row of numbered entries of the same width: logic [7:0] mem [0:1023] has 1,024 entries of 8 bits, and mem[addr] is the one that addr picks. Lesson 6.3 Block RAM and DSP blocks
arrival time
When a path's data gets there: after the clock-to-output time, the logic and the wires. Lesson 8.2 The critical path and slack
assign
Connects a signal to the logic that drives it, for good: whenever an input changes, the signal follows. assign lines all work at once, so their order does not matter. Lesson 0.2 HDL describes hardware, and it all works at once
ASYNC_REG
An attribute that marks a synchroniser's flip-flops, so that Vivado places them close together and its clock domain crossing (CDC) report recognises them. Lesson 9.2 The two-flop synchroniser
asynchronous FIFO
A FIFO written on one clock and read on another, whose counts cross in Gray code. It carries one value per cycle between clocks. Lesson 9.4 Asynchronous FIFOs and resets
asynchronous input
An input that changes whenever it likes, not on the reading clock's edges, such as a button or a signal from another clock. Sooner or later it changes inside a flip-flop's window. Lesson 9.1 Metastability
asynchronous reset
A reset that acts the moment it rises, without waiting for the clock. It is written as a second event in the block's event list. Lesson 2.3 Reset: synchronous and asynchronous
attribute
A note to Vivado written in the code, between (* and *), about the declaration after it, such as ASYNC_REG. Lesson 9.2 The two-flop synchroniser

B

backpressure
A sink holding its source back by setting ready to 0. Lesson 10.1 Valid and ready
bank
One of several memories side by side, each with its own read, over which a map is split so that neighbouring positions can be read in one cycle. Lesson 11.2 Four taps a cycle
base
The first of the neighbouring positions that a read from banks fetches together. Lesson 11.2 Four taps a cycle
baud rate
A serial line's speed in bits a second: 115,200 in this course. Both ends must use the same. Lesson 7.3 Programming the board
bias
The number a layer adds to each of its sums, one for each output channel, found when the network was trained. Lesson 11.1 A decoder made of convolutions
binary encoding
A state encoding with the fewest bits that give every state a code of its own: three states in two bits, 00, 01 and 10. Lesson 5.3 Encodings and safe defaults
bit
One binary digit, 0 or 1. A logic signal with no range is one bit. Lesson 1.1 Signals, vectors and assign
bit-select
One bit of a vector, taken by its number: sum[4] is bit 4 of sum. Lesson 1.1 Signals, vectors and assign
bitstream
The file a build ends with: the bits of every LUT and every routing connection. Programming loads it into the FPGA. Lesson 0.3 The build flow in one picture
bitwise operator
An operator that works on each bit of a vector separately, such as &, | and ~: ~ turns 0110 into 1001. Lesson 1.2 Operators become look-up tables
block RAM
A memory of 18 or 36 kilobits beside the FPGA's logic. Vivado can use one for an array your code reads at a clock edge. Lesson 6.3 Block RAM and DSP blocks
blocking assignment
=: the left-hand side changes at once, before the next line runs. Use it in always_comb; in always_ff, a later line would read the new value. Lesson 2.2 always_ff and why assignments use <=
bounce
What a button's contacts do for up to a few milliseconds when pressed or let go: touch and part, so the signal flips between 0 and 1 before it settles. Lesson 4.4 Debouncing a button
bus
A vector seen as one signal of several bits, such as count[3:0]. A waveform draws it as one lane, in hexadecimal. Lesson 3.2 Reading waveforms: X and Z
busy and done
Outputs that say a block is working, and that its result is ready. A controller that runs other blocks starts each with a pulse and waits on its done. Lesson 5.4 A state machine driving a datapath

C

carry
The part of a column's sum that passes to the next column. The sum of two N-bit numbers can carry out of the top bit, so it needs N + 1 bits. Lesson 1.1 Signals, vectors and assign
carry chain
Logic beside the LUTs that passes each carry of an addition straight to the next bit, without going through a LUT or the wiring between cells. Lesson 6.2 Adders and multiplexers
CARRY4
Four columns of a carry chain. CARRY4s join end to end, so a wide adder is one long chain. Lesson 6.2 Adders and multiplexers
case
A statement that runs the line whose value matches its expression, such as a multiplexer's select. Always end one with a default. Lesson 1.3 Multiplexers with ?:, if and case
cell
One of the FPGA's building blocks, such as a LUT. Vivado builds every design from cells. Lesson 0.1 What is inside an FPGA
channel
One of the values a map holds at each position, like one colour of an image. The 2D decoder's input has 4 channels and its hidden maps 9. Lesson 11.1 A decoder made of convolutions
clock
A signal that switches between 0 and 1, on and on, at a steady rate. Flip-flops act at its rising edges; the Arty's clock runs at 100 MHz, one cycle every 10 ns. Lesson 2.1 The clock and the D flip-flop
clock constraint
A create_clock line that tells Vivado a clock's period and the port it arrives on, so that it can check every path. It describes the clock and never sets it. Lesson 7.2 Describing the clock
clock domain
A clock and the logic it runs. A signal from another domain crosses through a synchroniser, a handshake or an asynchronous FIFO. Lesson 9.2 The two-flop synchroniser
clock enable (CE)
A flip-flop input that decides whether it takes D at a rising edge. Vivado joins a register's enable to the CE inputs, so the enable costs no logic. Lesson 2.4 Registers with enables
clock groups
A constraint that tells Vivado to treat two clocks as unrelated and leave the paths between them untimed: the design's synchronisers, handshakes and FIFOs must make them safe. Lesson 9.4 Asynchronous FIFOs and resets
clock network
Wires built to bring a clock to every flip-flop at almost the same moment, driven by a global clock buffer. Lesson 4.2 Clock enables, not divided clocks
clock skew
How much later a clock edge reaches a path's destination flip-flop than its source. Lesson 8.3 Reading a timing report
clock-to-output time
How long after a rising edge a flip-flop's output changes. Lesson 8.1 Setup and hold
code distance
How large a surface code is: a larger distance spreads a qubit over a larger grid and corrects more errors. At distance 5 the 2D decoder reads a 9 × 9 grid. Lesson 11.1 A decoder made of convolutions
combinational logic
Logic whose outputs depend only on its inputs as they are now, with no memory: what assign and always_comb describe. Lesson 1.3 Multiplexers with ?:, if and case
concatenation
Braces that join vectors and bits into one wider vector, the leftmost part at the top: {q[2:0], d} is four bits. Lesson 4.3 Shift registers and edge detection
conditional operator
A choice on one line: the condition, then ?, then the value for 1, then :, then the value for 0. Lesson 1.3 Multiplexers with ?:, if and case
configuration memory
Where the FPGA keeps the bitstream's bits, beside the logic they set up. It forgets everything when the power goes off. Lesson 7.3 Programming the board
constraints file (XDC)
A file in Vivado's XDC format that says what the code does not: which pin each port uses, and what voltage each pin's signals use. Lesson 0.3 The build flow in one picture
controller
A state machine that tells a datapath what to do, and when. Lesson 5.4 A state machine driving a datapath
convolution
At each position of a grid, a bias plus each input in a window around the position times its weight, over every input channel. Each output channel has its own weights and bias, and so its own sum. The decoders' layers are convolutions. Lesson 11.1 A decoder made of convolutions
counter
A register that adds one at each rising edge. Designs count the cycles between two events, the addresses of a memory and the values that have arrived. Lesson 4.1 Counters
critical path
The path with the least slack. It sets how fast the clock can be, and its slack is WNS. Lesson 8.2 The critical path and slack
cycle
The time from one rising edge of the clock to the next: 10 ns on the Arty. A waveform with a clock has one column per cycle. Lesson 2.1 The clock and the D flip-flop

D

D flip-flop
The cell that remembers one bit: at each rising edge it copies its input d to its output q, which keeps that value until the next edge. Lesson 2.1 The clock and the D flip-flop
datapath
The registers and arithmetic that do a design's work, told what to do by a controller. Lesson 5.4 A state machine driving a datapath
debouncer
A circuit that believes a change of a button's signal only once it has lasted long enough, such as 10 ms, so that a bouncing press counts once. Lesson 4.4 Debouncing a button
default
The line of a case that covers every value no other line lists. Always write one: lesson 1.4 shows the latch a missing one can build. Lesson 1.3 Multiplexers with ?:, if and case
default assignment
A first line in a block that gives every output a value, which the lines after it may change. In always_comb it makes sure that no path builds a latch. Lesson 1.4 The accidental latch
delay (#)
#5: wait 5 time units. Only a simulator can wait like this; synthesis drops delays. Lesson 3.1 Anatomy of a testbench
design under test
The design a testbench tests: one instance of it inside the testbench, often named dut. Lesson 0.4 The tools and what each does
distributed RAM
Memory built from LUTs: a LUT6 used this way holds 64 bits. Vivado uses it for an array read with no clock edge. Lesson 6.3 Block RAM and DSP blocks
divided clock
A slower clock made from a faster one, such as a counter bit. It works in simulation but is a trap on the chip: keep one clock, and use a tick as an enable. Lesson 4.2 Clock enables, not divided clocks
DSP block
A block that holds a multiplier, an adder after it, and registers, for multiplications that would otherwise take many LUTs. Lesson 6.3 Block RAM and DSP blocks
DSP48E1
This FPGA's DSP block, which multiplies a 25-bit number by an 18-bit one. Lesson 6.3 Block RAM and DSP blocks

E

edge detector
A 2-bit shift register and one gate that turn a level into a pulse: 1 for one cycle, in the cycle after the level rose. Lesson 4.3 Shift registers and edge detection
empty cycle
A cycle with no tap in it, which a layer that must wait sends down its pipeline, so that nothing it has half done is lost. Lesson 11.4 Layers that wait
enable
A signal that says when something may happen: a latch follows its input while its enable is on, and holds its value while it is off. Lesson 1.4 The accidental latch
endpoint
Where a path ends, such as a flip-flop's D input. A timing summary counts the failing ones. Lesson 8.2 The critical path and slack
engine
The hardware that works out one layer of the 3D decoder. Its four engines run at once, each on a different voxel. Lesson 12.1 A decoder that sees time
enumerated type (enum)
A type whose values have names. A typedef enum lets code say CLOSED and OPEN while the register holds numbers. Lesson 5.1 States, transitions and outputs
event list
The part in brackets after @, such as (posedge clk): the events that make a block run. It is also called the sensitivity list. Lesson 2.3 Reset: synchronous and asynchronous

F

falling edge
The instant a clock goes from 1 to 0. This course's testbenches change a design's inputs on falling edges (lesson 3.1), so that the inputs are steady at every rising edge. Lesson 2.1 The clock and the D flip-flop
FDCE
A flip-flop whose clear input, CLR, works without the clock: what Vivado builds for an asynchronous reset to 0. Lesson 2.3 Reset: synchronous and asynchronous
FDRE
Vivado's name for this FPGA's usual flip-flop: a D flip-flop with a clock enable (CE), which can make it skip an edge, and a reset (R), which can clear it. Lesson 2.1 The clock and the D flip-flop
FIFO
First in, first out: a memory that holds several values and hands them on in the order they came, so that a source and a sink can each run at their own pace for a while. Lesson 10.2 Synchronous FIFOs
FPGA
A field-programmable gate array: a chip whose circuit you choose after it is made. Load a different design into it and it becomes a different circuit. Lesson 0.1 What is inside an FPGA
framing
The start bit before each byte on a serial line and the stop bit after it. A receiver that finds the stop bit at 1 where it should be has the framing right. Lesson 10.3 A UART receiver

G

gate
A small circuit that works out one operation, such as "and" or "or". On an FPGA, Vivado folds the work of several gates into one LUT. Lesson 0.2 HDL describes hardware, and it all works at once
global clock buffer (BUFG)
The cell that drives a clock network, so that the clock reaches every flip-flop at almost the same moment. Lesson 4.2 Clock enables, not divided clocks
Gray code
A way of counting in which each value differs from the next in one bit only, so a synchroniser that catches a change sees the old count or the new one, never a mixture. Lesson 9.4 Asynchronous FIFOs and resets

H

handshake
Two signals with which two parts agree that a value has passed: valid and ready on one clock (lesson 10.1), or a request and an answer, each through a synchroniser, between clocks (lesson 9.3). Lesson 9.3 Pulses, handshakes and buses
hardware description language (HDL)
A language that describes a circuit, not steps to run: each assign line is a piece of the circuit, and all the pieces exist at once and work all the time. Lesson 0.2 HDL describes hardware, and it all works at once
harness
The design around a core on the board: it receives a frame from the computer, starts the core, and sends back the core's results and the number of cycles the core counted. Lesson 12.4 A stale done
hexadecimal
Numbers written in base 16, with the digits 0 to 9 and then A to F for 10 to 15. One hex digit is exactly four bits, so waveforms write vectors in hexadecimal. Lesson 1.1 Signals, vectors and assign
hold time
How long after a rising edge a flip-flop's input must still hold still. Lesson 8.1 Setup and hold

I

I/O standard
The voltage a pin's signals use and the way they are driven. Every pin in this course is LVCMOS33, 3.3 V CMOS. Lesson 7.1 Pins and I/O standards
implementation
Vivado's steps after synthesis: tidying the netlist, then place and route. Its result is what the bitstream is made from. Lesson 10.4 Debugging on the board
initial block
A block that runs once, from time 0, one line after another, waiting wherever a line says so. This course uses it in testbenches only. Lesson 3.1 Anatomy of a testbench
input buffer (IBUF)
The cell that joins an input pin to the logic inside the chip. Synthesis adds one for each input pin. Lesson 0.3 The build flow in one picture
input group
The input channels an engine takes at once: 8, so 128 input channels come in 16 groups. Lesson 12.3 One counter for everything
instance
One copy of a module placed inside another, with each of its ports joined to a signal, such as the design under test inside its testbench. Lesson 3.1 Anatomy of a testbench
integrated logic analyser (ILA)
A circuit Vivado builds into your design from the FPGA's own logic and block RAM, which records chosen signals as the chip runs and shows them in Vivado as a waveform. Lesson 10.4 Debugging on the board

J

jitter
The small random wobble in when each clock edge arrives. A timing report allows for it as clock uncertainty, which takes a little off the time a path has. Lesson 8.3 Reading a timing report

K

kernel
The window a convolution reads around each position, such as 11 × 11. Lesson 11.1 A decoder made of convolutions

L

lane
One of the words a read from banks puts out, in order: lane j holds position base + j, whichever bank it came from. In the 3D decoder, one row of an engine's arithmetic, with its own running sum. Lesson 11.2 Four taps a cycle
latch
A memory that follows its input while its enable is on and holds its value while it is off. A path through always_comb that gives an output no value builds one, almost always by mistake. Lesson 1.4 The accidental latch
latency
How many cycles after a value goes in its result comes out; a pipeline's stages add to it. Lesson 8.4 Pipelining a failing path
layer
One step of a network, from one map to the next; in the decoders each is a convolution. A hidden layer is any layer but the last. Lesson 11.1 A decoder made of convolutions
lint
Checking code for likely mistakes without running it. This course lints every file with Verilator, and every correct example passes. Lesson 0.4 The tools and what each does
logic
The SystemVerilog word that declares a signal, a wire that carries 0 or 1, as in logic opening;. Lesson 0.2 HDL describes hardware, and it all works at once
logic level
One cell of logic on a path between two flip-flops. A timing report counts them under Logic Levels. Lesson 8.3 Reading a timing report
logit
The last layer's sum. The decision is 1 when it is more than 0, so a logit of 0 gives 0. Lesson 11.1 A decoder made of convolutions
look-up table (LUT)
A tiny memory that holds a truth table: its inputs form an address that picks a row, and the bit stored there is the output. Each LUT on the course's FPGA has six inputs, so it can compute any function of up to six. Lesson 0.1 What is inside an FPGA

M

map
A grid of values with one or more channels at each position: a layer's input or its output. Lesson 11.1 A decoder made of convolutions
master XDC
Digilent's constraints file for a board, with a line for every pin you are likely to use, each turned off with a #. You copy the lines you need and rename the ports. Lesson 7.1 Pins and I/O standards
metastability
A flip-flop's output hanging between 0 and 1 for a while, after its input changed too close to an edge, then settling to 0 or 1 with no telling which. Lesson 9.1 Metastability
mixed precision
Weights of different widths in different layers, such as 4 bits in the two largest layers and 8 (16 for the skip connection) in the rest, to save memory where it costs least. Lesson 12.1 A decoder that sees time
MMCM
Mixed-mode clock manager: a block inside the FPGA that makes a new clock from the board's. The two clocks keep a fixed relationship. Lesson 9.4 Asynchronous FIFOs and resets
module
A named piece of hardware in SystemVerilog, with its ports listed at the top. A design is built from modules, and a testbench is a module too. Lesson 0.2 HDL describes hardware, and it all works at once
multiplexer
A circuit that passes one of its inputs to its output, with a select signal saying which. Each output bit costs one LUT while it depends on six inputs or fewer. Lesson 1.3 Multiplexers with ?:, if and case
MUXF7
A fixed multiplexer after the LUTs that picks between the outputs of two LUT6s, so an 8-to-1 multiplexer takes two LUTs and a MUXF7. Lesson 6.2 Adders and multiplexers
MUXF8
A fixed multiplexer that picks between the outputs of two MUXF7s. Lesson 6.2 Adders and multiplexers

N

net
A wire in a netlist, joining pins of cells. Lesson 6.1 What synthesis builds
netlist
What synthesis makes from your code: a list of the chip's cells, and the nets that join their pins. Lesson 6.1 What synthesis builds
next-state logic
The logic that works out, from the state and the inputs, the state a machine will go to at the next rising edge. Lesson 5.2 The two-block template
nonblocking assignment
<=: at a clock edge, every right-hand side is read first, with the values from just before the edge, and only then do the left-hand sides change, all together. Use it in always_ff. Lesson 2.2 always_ff and why assignments use <=

O

one-hot encoding
A state encoding with a bit for each state, of which exactly one is 1. It takes more flip-flops, but each state is a single bit. Lesson 5.3 Encodings and safe defaults
output buffer (OBUF)
The cell that joins the logic inside the chip to an output pin. Synthesis adds one for each output pin. Lesson 0.3 The build flow in one picture
output enable
A signal that says when an output drives its pin. While it is 0, the output lets go and the pin is Z. Lesson 3.2 Reading waveforms: X and Z
output group
The output channels an engine makes at once: 16, so 128 output channels come in 8 groups. Lesson 12.3 One counter for everything
output register
An optional register inside a block RAM, after its read. The word comes a cycle later, but leaves the block early in its cycle. Lesson 11.3 Data two cycles late

P

package pin
One of the balls under the chip, 324 on this FPGA, through which a port reaches the board. A constraints file names the pin for each port. Lesson 7.1 Pins and I/O standards
padding
A border of zeros around a stored grid, so that a kernel that reaches past the edge reads 0 there. Where a map is stored without one, a tap outside the grid is masked: its product is forced to 0 (lesson 11.3). Lesson 11.1 A decoder made of convolutions
parameter
A constant of a module that each instance can set to its own value, such as a width or a last count. The value after = is the default. Lesson 4.1 Counters
parity bit
A check bit that some serial links add to each character. The course's serial lines send none, so a terminal must be set to expect none. Lesson 7.3 Programming the board
part-select
Some of a vector's bits, taken by their range: sum[3:0] is bits 3 to 0 of sum. Lesson 1.1 Signals, vectors and assign
path
The way from one flip-flop to the next, on one clock or between two: the first's clock-to-output time, then the logic and the wires, to the second's input. Lesson 8.1 Setup and hold
period
The time from one rising edge of a clock to the next: 10 ns for the Arty's 100 MHz clock. Lesson 7.2 Describing the clock
pipeline
A design split by registers into stages, so that each long path becomes several short ones, each with a whole clock period. Lesson 8.4 Pipelining a failing path
place and route
The build step that puts each cell somewhere on the chip and wires the cells together and to the pins the constraints file named. Lesson 0.3 The build flow in one picture
port
One of a module's inputs or outputs, listed at the top of the module. Lesson 0.2 HDL describes hardware, and it all works at once
probe
One of the nets an ILA records. Lesson 10.4 Debugging on the board
pulse
A signal that is 1 for one cycle, to make something happen once. Lesson 4.3 Shift registers and edge detection

R

RAMB18E1
Vivado's name for this FPGA's 18-kilobit block RAM. Lesson 6.3 Block RAM and DSP blocks
range
The brackets after logic that say which bits a vector has: [3:0] is four bits, numbered 3 down to 0. Lesson 1.1 Signals, vectors and assign
raster order
Along a row and then the next row down: the order in which a map's positions are numbered, and in which the decoders write their maps. Lesson 11.2 Four taps a cycle
read latency
How many rising edges after its address a memory's word arrives: one for a block RAM, two with its output register. Lesson 11.3 Data two cycles late
readiness count
A count of the positions a layer has written, which tells the next layer when everything it reads is there. It counts finished writes; it is not a timer. Lesson 11.4 Layers that wait
reference model
The same behaviour as the design, written the simplest way you can trust, inside a testbench to give the right answers. Lesson 3.3 Self-checking testbenches
register
A row of flip-flops on one clock that holds a number: what you get when you assign a vector in always_ff. Lesson 2.4 Registers with enables
ReLU
Turns negative sums into 0 and leaves the rest as they are. The decoders apply it after each hidden layer. Lesson 11.1 A decoder made of convolutions
requantiser
The step after a hidden layer that turns each finished sum back into an 8-bit activation: ReLU, a multiplier, a rounded shift and a clip to 255. Lesson 12.2 Back to eight bits
required time
When a path's data must arrive: the next rising edge, less the setup time. Lesson 8.2 The critical path and slack
reset
A signal that puts flip-flops back to a value you choose: when the design starts, or whenever you want to start again. Lesson 2.3 Reset: synchronous and asynchronous
reset synchroniser
Two flip-flops that pass a reset into a clock domain. The reset starts at once, through their asynchronous preset, and ends at a clock edge, so everything leaves reset together. Lesson 9.4 Asynchronous FIFOs and resets
rising edge
The instant a clock goes from 0 to 1, when flip-flops take their inputs. This course's diagrams mark each one with a small arrowhead. Lesson 2.1 The clock and the D flip-flop
rounding
Taking the nearest whole number, not the one below. Before a shift right by S bits, add half of 2 to the power S. Lesson 12.2 Back to eight bits
route delay
The part of a path's delay spent in the wires between cells, not inside them. Lesson 8.3 Reading a timing report

S

safe state
The state that default in the next-state logic sends a machine to from a code no state uses, instead of leaving it stuck. Lesson 5.3 Encodings and safe defaults
sample depth
How many samples an ILA's memory holds: 1024 samples at 100 MHz cover 10.24 µs. Lesson 10.4 Debugging on the board
saturation
Clipping a result that is too large to the largest value that fits, such as 255 in 8 bits, instead of letting it wrap round to a small number. Lesson 12.2 Back to eight bits
self-checking testbench
A testbench that works out the right answer itself, compares after every cycle, and ends with one verdict: TEST PASSED or TEST FAILED. Lesson 3.3 Self-checking testbenches
sequencer
The counters that choose which tap a layer issues next. Each layer of the banked decoder has its own, so each starts a position as soon as its inputs are written. Lesson 11.4 Layers that wait
serial terminal
A program, such as PuTTY or screen, that shows as text what arrives on a serial port, such as the board's UART. Lesson 7.3 Programming the board
setup time
How long before a rising edge a flip-flop's input must already hold still. Lesson 8.1 Setup and hold
shift register
A row of flip-flops in which, at every rising edge, each bit takes the value of the bit before it and the first takes a new input. Lesson 4.3 Shift registers and edge detection
shift register LUT (SRL16E)
A LUT working as a shift register of up to 16 bits, with no flip-flops; one LUT can hold up to 32. It cannot be reset, so a shift register with a reset takes flip-flops instead. Lesson 4.3 Shift registers and edge detection
sign bit
The top bit of a signed vector: the value is negative exactly when it is 1. Lesson 11.1 A decoder made of convolutions
signal
A wire in a design, which carries 0 or 1. logic declares one, and a vector is a signal of several bits. Lesson 0.2 HDL describes hardware, and it all works at once
signed
A vector read as two's complement, in which the top bit counts negative: in 8 bits it counts −128, so all ones is −1. Lesson 11.1 A decoder made of convolutions
simulator
A program that runs your design's code on your computer as if it were hardware: in seconds, with every signal visible. This course simulates with Icarus Verilog. Lesson 0.4 The tools and what each does
sized number
A number with its width and its base written in: 2'd1 is 2 bits wide, written in decimal, value 1, and 4'b0110 is 4 bits written in binary, value 6. Lesson 1.3 Multiplexers with ?:, if and case
skip connection
A path that takes a network's inputs past some of its layers, straight to a later one. Lesson 12.1 A decoder that sees time
slack
A path's time to spare: for setup, its required time minus its arrival time; for hold, the other way round. A negative slack fails. Lesson 8.2 The critical path and slack
slice
One of the small groups of LUTs and flip-flops the chip is built from, which is why the Utilization report says Slice LUTs and Slice Registers. Lesson 6.4 Reading the utilisation report
slot
In the 3D decoder's first design, the 3,456 cycles a hidden engine takes for one voxel: all four engines start their next voxels together, once a slot. Its later builds drop it. Lesson 12.3 One counter for everything
source and sink
The part of a design that gives values, and the part that takes them. Lesson 10.1 Valid and ready
stage
One part of a pipeline, between two registers. Lesson 8.4 Pipelining a failing path
stale
Left over from an earlier run, such as a done that is still 1 from the last run. Lesson 12.4 A stale done
start
An input pulse that begins a block's job. Lesson 5.4 A state machine driving a datapath
state
One of the places a state machine can be in, such as a door's closed, open or locked. The state register holds a code for it. Lesson 5.1 States, transitions and outputs
state encoding
Which code goes with which state of a state machine. Vivado may choose its own, whatever the enum says. Lesson 5.3 Encodings and safe defaults
state machine
A design that remembers where it is in a sequence: a register holds its state, and at each clock edge the state and the inputs decide the next one. Lesson 5.1 States, transitions and outputs
state register
The register that holds a state machine's state. In the two-block template it only takes the next state at each rising edge. Lesson 5.1 States, transitions and outputs
step
One column of a waveform with no clock: a stretch of time, 10 ns in this course's waveforms, in which each signal holds one value. Lesson 0.1 What is inside an FPGA
synchroniser
Two flip-flops in a row on the clock that reads an asynchronous input. The first may hang; the second takes its output a cycle later, almost always settled. Lesson 9.2 The two-flop synchroniser
synchronous reset
A reset that a flip-flop looks at only at rising edges of its clock, like any other input. This course uses them unless a lesson says otherwise. Lesson 2.3 Reset: synchronous and asynchronous
syndrome
In quantum error correction, the pattern of checks that failed. Different errors can give the same syndrome, so a decoder guesses which corrections to apply. Lesson 11.1 A decoder made of convolutions
synthesis
The first step of a build: Vivado turns your code into the FPGA's cells, such as LUTs, flip-flops and pin buffers, and the wires between them. Lesson 0.3 The build flow in one picture
synthesisable
Code that synthesis can build from the FPGA's cells. Delays, $display and $finish build nothing, and a block on both edges of one clock is refused. Lesson 3.4 What simulates but cannot be built
SystemVerilog
The hardware description language this course uses, for its designs and for its testbenches. Lesson 0.2 HDL describes hardware, and it all works at once

T

tap
One input a kernel reads, at one place in its window. Lesson 11.1 A decoder made of convolutions
task
A named list of testbench lines that you can use again, such as one that sets the inputs, waits and checks the output. Lesson 0.4 The tools and what each does
terminal count
The value after which a counter starts again from 0. For a tick once in every N cycles it is N − 1, because the count starts at 0. Lesson 4.1 Counters
testbench
A module that sets a design's inputs over time and checks its outputs. It is never built into hardware. Lesson 0.4 The tools and what each does
tick
A signal that is 1 for one cycle in every N. As an enable, it makes registers act less often while every register stays on one clock. Lesson 4.2 Clock enables, not divided clocks
tile
A small block of arithmetic that an engine reuses over the kernel's taps and the channels. Lesson 12.3 One counter for everything
timing summary
Vivado's report on timing, timing_summary.rpt: what could not be checked, WNS and TNS, the clocks, then the worst paths. Lesson 6.4 Reading the utilisation report
TNS (total negative slack)
The negative slacks of the failing endpoints, added up: 0 when every path meets timing. Lesson 8.2 The critical path and slack
toggle
A signal that flips at every pulse and then holds still, so that a pulse can cross to another clock as a change of level. Lesson 9.3 Pulses, handshakes and buses
transition
A move from one state to another at a clock edge, drawn as an arrow labelled with the input that takes it. Lesson 5.1 States, transitions and outputs
tri-state buffer (OBUFT)
An output buffer that can stop driving its pin, which Vivado builds for an output with an output enable. Lesson 3.2 Reading waveforms: X and Z
trigger
The condition that makes an ILA keep its samples: when it comes true, the ILA keeps that moment and the samples around it. Lesson 10.4 Debugging on the board
truth table
Every combination of a circuit's inputs, with the output for each. A LUT holds one. Lesson 0.1 What is inside an FPGA
two-block template
How this course writes state machines: an always_comb block for the next-state logic, starting with a default assignment, and an always_ff block for the state register. Lesson 5.2 The two-block template

U

UART
Universal asynchronous receiver-transmitter: a circuit that sends or receives bytes one bit at a time on one wire, each between a start bit and a stop bit, at an agreed baud rate. Lesson 7.3 Programming the board
UART receiver
A circuit that turns a serial line back into bytes: it waits for a start bit, then reads each bit in its middle, counting cycles of its own clock. Lesson 10.3 A UART receiver
unsigned
A vector read as a plain binary number, never negative: 8 bits hold 0 to 255. If one operand of an expression is unsigned, the whole expression is worked out unsigned. Lesson 12.1 A decoder that sees time
Util%
A column of the Utilization report: Used as a percentage of Available, for each kind of resource. Lesson 6.4 Reading the utilisation report
utilisation
How much of each kind of resource on the chip a design uses, against how many the chip has. Vivado reports it in its Utilization report. Lesson 6.4 Reading the utilisation report
Utilization report
Vivado's count of the cells a design uses and how many the chip has, table by table, written after synthesis and again after place and route. Lesson 0.3 The build flow in one picture

V

valid and ready
Two signals that pass values between two parts of a design: valid says a value is on offer, ready says it can be taken. A value moves at a rising edge where both are 1. Lesson 10.1 Valid and ready
vector
Bits grouped under one name to hold a number. In logic [3:0] a, bit 0 is worth 1, bit 1 is worth 2, and each bit is worth twice the one below it. Lesson 1.1 Signals, vectors and assign
voxel
A position in a volume: one cell of a grid in space and time. Lesson 12.1 A decoder that sees time

W

waveform
A drawing of signals over time, with time running from left to right: a line drawn high is 1, and a line drawn low is 0. Every waveform on this site comes from a simulation. Lesson 0.1 What is inside an FPGA
waveform file (VCD)
The file a simulation writes, in the VCD (value change dump) format, with every recorded signal's changes over time. A waveform viewer draws it. Lesson 0.4 The tools and what each does
waveform viewer
A program, such as Surfer or GTKWave, that draws a waveform file as waveforms. Lesson 0.4 The tools and what each does
weight
A number a trained network multiplies one input by. Training found them; the decoders' hardware only stores and uses them. Lesson 11.1 A decoder made of convolutions
WHS (worst hold slack)
The smallest hold slack of any path in a design. Positive means every path holds its data long enough after the edge. Lesson 8.3 Reading a timing report
width
The number of bits in a vector, which sets the largest number it can hold: four bits hold 0 to 15, and each extra bit doubles the number of values. Lesson 1.1 Signals, vectors and assign
WNS (worst negative slack)
The first number of a timing summary: the smallest time to spare on any path from one flip-flop to the next, in nanoseconds. Positive means every path arrives in time. Lesson 7.2 Describing the clock

X

X (unknown)
A simulator's value for a bit it cannot know, drawn hatched: one the code never set, one that does not exist, or one worked out from such a bit. On the chip every bit is 0 or 1. Lesson 3.2 Reading waveforms: X and Z

Z

Z (high impedance)
A simulator's value for a wire that nothing drives, drawn on the half-way line. Inside an FPGA every wire has a driver, so only a pin can let go. Lesson 3.2 Reading waveforms: X and Z
