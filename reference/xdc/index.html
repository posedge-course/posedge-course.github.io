Reference

XDC snippets

A constraints file says what the code cannot: which pin each port uses, what signals the pin carries, and how fast the clock runs. Every snippet here is lines of a file that one of the course's Vivado builds for the Arty A7 used. For pins not shown here, copy the lines from Digilent's master XDC rather than typing them.

Switches and an LED

  • set_property PACKAGE_PIN ties a port, named by get_ports, to one pin of the chip.
  • IOSTANDARD LVCMOS33 says the pin carries 3.3 V signals, as every pin in this course does.
  • A port with no pin, or a pin with no standard, stops the build at the bitstream step.

Buttons, and a bus a bit at a time

  • A bus takes one line a bit, with the bit in braces: {d[0]}. d[*] names every bit.
  • The four push buttons, BTN0 to BTN3, read 1 while pressed and 0 the rest of the time.
  • The master XDC counts its LEDs from 0 where the board's labels do not: its led[0] is the LED marked LD4.

The clock

  • The board's 100 MHz oscillator reaches the chip on pin E3.
  • create_clock describes it: -period 10.00 is the time between rising edges in nanoseconds, and sys_clk_pin a name the reports use. It never sets how fast the board runs. Leave it out and Vivado checks no path at all.

The serial line

In the master XDC's names, rxd and txd are from the PC's point of view, and the _in or _out at the end is the FPGA's: uart_rxd_out is the FPGA's output, which the PC receives. A serial terminal on the PC must use the design's baud rate.

Two clocks

  • Vivado makes a clock for an MMCM's output by itself, the MMCM being the FPGA's clock manager (level 9's project), and works out its period from the MMCM's settings. create_generated_clock with only a name and a pin renames that clock, so the reports and the next line can call it clk_b.
  • set_clock_groups -asynchronous tells Vivado that the two clocks are unrelated, so it leaves the paths between them to the design. Each must cross safely: a single signal through a synchroniser, a value with a handshake or an asynchronous FIFO (lessons 9.2 to 9.4).

Debug nets

MARK_DEBUG keeps a net and its name through synthesis, so that an integrated logic analyser can record it. The attribute (* mark_debug = "true" *) on the net's declaration does the same.
