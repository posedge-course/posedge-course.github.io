Reference

The Vivado flow

Vivado turns your design files and a constraints file into a bitstream in fixed steps, and writes reports on the way. A build takes minutes and a simulation seconds, so simulate first.

The steps

Each step of a build, what it does, and what to read after it
StepWhat it doesRead after it
SynthesisTurns the code into a netlist of the chip's cells: LUTs, flip-flops, carry chains, block RAM, DSP blocks and pin buffersThe Utilization report after synthesis: no latch, and none of your logic removed
ImplementationTidies the netlist, places each cell on the chip, and routes the wires between the cells and to the pinsThe timing summary, and the Utilization report after place and route
BitstreamWrites every LUT's bits, every flip-flop's start value and every routing switch into one file. It stops if a port has no pin or a pin no I/O standardIts messages, if it stops
ProgrammingSends the bitstream over the USB cable into the FPGA, which keeps it until the power goes offThe board's DONE LED, lit

In the Vivado window

The projects' board steps use the Vivado window and its Flow Navigator:

  1. Create an RTL project for the part xc7a100tcsg324-1, or xc7a35ticsg324-1L on an Arty A7-35T. A bitstream works only on the part it was built for.
  2. Add your .sv files as design sources and your .xdc file as a constraints file. With several modules, make the one at the top the top module.
  3. Run Generate Bitstream. It runs synthesis and implementation first.
  4. Under Implementation, click Open Implemented Design, then Report Utilization or Report Timing Summary.
  5. Connect the board by USB. Open the Hardware Manager, then Open Target, Auto Connect and Program Device.

Which report to read

The reports the course's builds write, and what to read each one for
ReportRead it for
utilization_synth.rptLatches (Register as Latch), and logic synthesis removed because nothing reads it
utilization.rptWhat the design takes from the chip, once place and route have tidied the netlist
timing_summary.rptRegisters with no clock, and whether every path meets the clock: WNS, TNS and the worst paths
cdc.rptWith two clocks: every path from one to the other, and whether a synchroniser guards it
clock_interaction.rptWith two clocks: how Vivado treats each pair, such as asynchronous clock groups
debug_core.rptWith an integrated logic analyser: its settings and its probes

The first lines of each report name the design and the part; most also name the step it comes from, as Design State: Synthesized or Routed.
